# 验收说明

> 本文档为嵌入式开发者完成 ESP32-C2 移植后提供自验清单。按四个层次逐级验收：编译 → 接口 → 流程 → 异常。

## 1. 验收环境要求

| 项目 | 要求 |
|------|------|
| 硬件 | ESP32-C2 开发板（ESP8684） |
| ESP-IDF | v5.3 或更新版本 |
| 上位机 | PC 运行 TactileSense Demo（含配网界面） |
| 网络 | 2.4GHz WiFi 路由器（用于 STA 连接），上位机与设备在同一局域网 |
| 串口 | USB 转 UART，115200 bps，用于日志输出 |
| 标签 | 设备 WPA2 密码打印在标签上，PIN 码通过日志/串口输出 |

## 2. 编译验收

### A1. ESP-IDF 环境验证

- **目的**：确认工具链可用
- **操作**：运行 `idf.py --version`，确认版本号 ≥ 5.3
- **通过标准**：输出版本号，无错误
- **失败处理**：重新安装 ESP-IDF 或检查 PATH 环境变量

### A2. 全量编译

- **目的**：确认所有源文件可编译
- **操作**：在 `firmware/esp32c2/` 目录执行 `idf.py build`
- **通过标准**：编译完成，0 error，0 warning
- **失败处理**：根据编译错误修正代码，常见问题：缺少 include 路径、符号未定义、API 版本不匹配

### A3. Flash 分区检查

- **目的**：确认 NVS 分区存在且大小足够
- **操作**：检查 `partitions.csv` 或 sdkconfig 中的分区配置
- **通过标准**：NVS 分区 ≥ 24KB
- **失败处理**：修改分区表增加 NVS 分区大小

## 3. 接口验收（29 个接口逐项测试）

### 3.1 生命周期

| 编号 | 接口 | 测试方法 | 通过标准 |
|------|------|---------|---------|
| B1 | init | 设备上电，检查串口日志 | 输出初始化完成日志，无崩溃 |
| B2 | deinit | 在测试程序中调用 deinit 后再 init | 无内存泄漏，可重复初始化 |

### 3.2 WiFi 介质

| 编号 | 接口 | 测试方法 | 通过标准 |
|------|------|---------|---------|
| B3 | wifi_scan | 调用扫描，打印扫描结果 | 返回附近 AP 列表，含 RSSI 和频段信息 |
| B4 | wifi_sta_connect | 提供正确的 SSID/密码连接 | 连接成功，返回 DEMO_OK |
| B5 | wifi_sta_connect（错误密码） | 提供错误密码连接 | 返回 DEMO_ERR，reason=202（AUTH_FAIL） |
| B6 | wifi_sta_connect（不存在AP） | 提供不存在的 SSID | 返回 DEMO_ERR，reason=201（NO_AP_FOUND） |
| B7 | wifi_sta_disconnect | 连接后再断开 | 断开成功，WIFI_EVENT_STA_DISCONNECTED 触发 |
| B8 | wifi_ap_start | 调用开启热点 | 手机可扫描到 Modu_XXXX，WPA2 加密 |
| B9 | wifi_ap_stop | 调用关闭热点 | 热点消失，手机扫描不到 |
| B10 | wifi_get_rssi | STA 连接后调用 | 返回 dBm 值（通常 -30 到 -80） |
| B11 | wifi_get_ip | STA 连接后调用 | 返回 DHCP 分配的 IPv4 地址 |
| B12 | wifi_get_current_ssid | STA 连接后调用 | 返回当前连接 WiFi 的 SSID |
| B13 | wifi_get_gateway | STA 连接后调用 | 返回当前网络的网关地址 |

### 3.3 TCP

| 编号 | 接口 | 测试方法 | 通过标准 |
|------|------|---------|---------|
| B14 | tcp_listen | 在设备上监听 5935 | 上位机可通过 telnet 连接 |
| B15 | tcp_accept | 上位机连接设备 TCP 服务器 | accept 返回客户端 socket |
| B16 | tcp_connect | 设备连接上位机 TCP 服务器 | 连接成功，可收发数据 |
| B17 | tcp_connect（超时） | 连接不存在的 IP | timeout_ms 后返回 DEMO_ERR |
| B18 | sock_send/recv | 连接后双向收发数据 | 数据完整、顺序正确 |
| B19 | sock_close | 关闭 socket | 对端检测到连接断开 |

### 3.4 UDP 组播

| 编号 | 接口 | 测试方法 | 通过标准 |
|------|------|---------|---------|
| B20 | udp_mcast_join | 加入 224.0.2.1:5936 | 无错误返回 |
| B21 | udp_send | 发送组播包到 224.0.2.1:5936 | 同网段其他主机可收到 |
| B22 | udp_recv | 接收上位机发送的 host_announce | 正确解析 JSON 报文 |

### 3.5 mDNS

| 编号 | 接口 | 测试方法 | 通过标准 |
|------|------|---------|---------|
| B23 | mdns_register | 注册服务 _tactile._tcp | 上位机可解析到此服务 |
| B24 | mdns_resolve | 解析上位机注册的服务 | 返回上位机 IP 和端口 |
| B25 | mdns_unregister | 注销服务 | 上位机解析不到 |

### 3.6 NVS

| 编号 | 接口 | 测试方法 | 通过标准 |
|------|------|---------|---------|
| B26 | nvs_set + nvs_get | 写入数据 → 重启 → 读取 | 读取数据与写入一致 |
| B27 | nvs_erase | 写入 → 擦除 → 读取 | 擦除后读取返回 DEMO_ERR 且 len=0 |
| B28 | nvs_get（不存在键） | 读取未写入的键 | 返回 DEMO_ERR，len=0 |

### 3.7 系统

| 编号 | 接口 | 测试方法 | 通过标准 |
|------|------|---------|---------|
| B29 | time_ms | 连续两次调用计算差值 | 差值 ≈ 实际等待时间（误差 <10ms） |
| B30 | random | 调用 1000 次统计分布 | 0/1 大致均匀，无连续重复值 |

## 4. 流程集成验收

### C1. 完整配网流程

- **目的**：验证从开箱到配网完成的全链路
- **操作**：
  1. 清除设备 NVS（模拟新设备）
  2. 设备上电 → 自动进入 AP 配网模式
  3. 上位机扫描到 Modu_XXXX 热点 → 连接 → 输入 PIN → 发送 wifi_config
  4. 设备连接目标 WiFi → 回复 ok → 关闭热点
- **通过标准**：设备连接目标 WiFi 成功，日志显示 `wifi_result: ok`
- **失败处理**：检查 WiFi 密码、PIN 码、2.4GHz 频段

### C2. 服务发现 — mDNS

- **目的**：验证 mDNS 一级发现
- **操作**：
  1. 设备配网成功后进入服务发现
  2. 上位机已在运行并注册了 mDNS 服务
- **通过标准**：设备解析到上位机 IP 和端口（日志显示 mDNS 解析成功）
- **失败处理**：检查上位机 mDNS 注册、防火墙

### C3. 服务发现 — 组播

- **目的**：验证 UDP 组播二级发现
- **操作**：
  1. 上位机停止 mDNS 服务（或模拟 mDNS 失败）
  2. 上位机保持组播 host_announce 发送
- **通过标准**：设备收到 host_announce，提取上位机 IP 和端口
- **失败处理**：检查路由器是否屏蔽组播

### C4. 服务发现 — 候选列表

- **目的**：验证三级保底发现
- **操作**：
  1. 先正常完成一次连接（让设备保存候选列表到 NVS）
  2. 重启后停止上位机 mDNS 和组播
  3. 设备应通过候选列表直连
- **通过标准**：设备 TCP 连接成功
- **失败处理**：检查 NVS 中候选列表是否写入

### C5. 注册握手

- **目的**：验证 device_hello / host_ack 协议
- **操作**：设备 TCP 连接上位机
- **通过标准**：
  - 设备发送 device_hello（含 MAC、fw_version、proto_ver）
  - 上位机回复 host_ack（含 heartbeat_interval、session_id、server_time）
  - 设备日志显示 "host_ack: ok"

### C6. 心跳保活

- **目的**：验证 ping/pong 心跳机制
- **操作**：设备保持连接 60 秒
- **通过标准**：
  - 设备每 10 秒发送 ping（seq 递增）
  - 上位机回复 pong
  - 上位机日志/界面显示设备在线

### C7. 心跳超时检测

- **目的**：验证判死机制
- **操作**：拔掉设备网线 / 关闭 WiFi
- **通过标准**：上位机 15 秒内标记设备离线

## 5. 异常场景验收

### D1. 配网密码错误

- **操作**：上位机发送错误的 WiFi 密码
- **通过标准**：设备回复 `wifi_result: fail, reason: 认证失败`

### D2. 配网 PIN 连续错误

- **操作**：连续发送 5 次错误 PIN
- **通过标准**：设备关闭热点，日志显示 PIN 锁定

### D3. TCP 断线重连

- **操作**：连接建立后，关闭上位机 TCP 服务器
- **通过标准**：
  - 设备检测到断线 → 退避重连
  - 上位机恢复后，设备自动重连成功

### D4. WiFi 断开重连

- **操作**：关闭目标 WiFi 路由器再开启
- **通过标准**：设备重新连接 WiFi → 自动进入服务发现 → 恢复连接

### D5. 上位机 busy 响应

- **操作**：模拟上位机连接数满（16+）
- **通过标准**：设备收到 busy → 60 秒长退避后重试

### D6. 上位机 host_bye 优雅退出

- **操作**：上位机正常退出（发送 host_bye）
- **通过标准**：设备立即停止等待通告，转候选直连 + 快速轮询

### D7. 看门狗

- **操作**：模拟某个状态长时间卡住
- **通过标准**：设备软重启，日志记录看门狗触发事件
