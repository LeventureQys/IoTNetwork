# beta v1.0.1 阶段三完成报告

## 1. 结论

阶段三开发、自动化测试和 Linux 设备 sudo启动测试已完成。真实设备成功使用 `10.42.0.1/24` 启动 AP/DHCP/TCP；制造首选网段冲突后成功自动切换到 `10.43.0.1/24`。停止后 AP接口、子进程、端口、pidfile、临时配置和 NAT规则均清理。

独立无线客户端 DHCP四步和 Windows PC端到端尚未执行，留待阶段四验收；不得据此宣告 Version整体完成。

## 2. 主要实现

- 新增严格热点配置、CIDR、DHCP池和候选计划模块。
- 默认真实 AP改为 `10.42.0.1/24`，NAT改为 false。
- 自动避让所有有效 IPv4直连路由，备用顺序为 `10.43.0.1/24`、`172.31.250.1/24`、`192.168.250.1/24`。
- 新增 rtnetlink路由采集、getifaddrs地址回读、单实例 flock和 argv子进程执行。
- dnsmasq使用 `--conf-file=/dev/null`、显式掩码、router和 option54 server-id。
- 新增 hostapd pid/身份等待和 dnsmasq PID/socket inode UDP67 readiness。
- NAT默认关闭；显式启用时只管理带所有权 comment、限制最终AP源网段的精确规则。
- AP启动失败进入 `provision_ap_backoff_ms`，不再约100ms重复启动。
- 模拟地址常量改为 `PROTO_SIM_AP_IP`，真实地址来自 DHCP router。
- 真实 backend初始化错误传播到设备入口，不创建状态机线程。

## 6. 实机过程中发现并修复

1. 当前 dnsmasq不支持具名 server-id，改为数字 option54。
2. hostapd后台 pidfile存在竞态，增加最多2秒 readiness等待。
3. 非 root被锁文件错误掩盖，权限检查前移。
4. 测试中非法模拟 tag和共享端口造成顺序依赖，已修正测试隔离。
