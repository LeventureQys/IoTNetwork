### 自决区

#### I1. 当前 dnsmasq 不支持具名 server-id option

- 问题描述：首次实机启动时 dnsmasq 输出 `bad command line options: bad dhcp-option`，拒绝 `--dhcp-option=option:server-id,...`。
- 自决方案：router 保持具名 `option:router`；server identifier 使用兼容的数字 option `--dhcp-option=54,<AP>`。
- 自决理由：DHCP option 54 数值是协议稳定定义，旧实现和当前设备 dnsmasq均已验证支持。
- 风险预警：文档和测试必须与实际 argv一致。
- 置信度：100%。

#### I2. hostapd 后台 pidfile 存在启动竞态

- 问题描述：备用网段首次实测中，hostapd 已输出 `AP-ENABLED`，但代码立即读取 pidfile和 `/proc` 身份时偶发失败，导致事务回滚。
- 自决方案：hostapd启动后最多等待20次、每次100ms，要求 pidfile和进程身份同时有效，再检查 AP模式。
- 自决理由：后台进程和 pidfile创建存在合理异步窗口；readiness等待比单次检查稳定且有明确2秒上限。
- 风险预警：超时后仍必须按所有权规则回滚。
- 置信度：100%。

#### I3. 新退避语义暴露既有测试数据不合法

- 问题描述：两个状态机测试使用 `dev_unconfirmed`、`dev_wifi_drift` tag，但模拟后端设备 tag契约要求 `dev0` 至 `dev15`。旧代码在 AP_PROVISION停留掩盖了启动失败，新退避会正确切到 BOOT。
- 自决方案：测试改用合法 `dev4`、`dev5` tag，并为状态机 fixture分配独立模拟端口范围，消除顺序依赖。
- 自决理由：修复测试输入而非回退正确退避行为。
- 风险预警：不得改变模拟设备数量上限和业务状态机语义。
- 置信度：100%。

#### I4. 非 root 初始化应先检查权限

- 问题描述：单实例锁文件由 root创建后，普通用户初始化会先报锁失败，掩盖真实权限原因。
- 自决方案：严格配置加载后、获取锁前检查 `geteuid()==0`；非 root明确报“真实 Linux 网络后端需要 root权限”，且不创建锁。
- 自决理由：错误诊断应指向首要前置条件，避免误导部署排障。
- 风险预警：配置本身非法时仍优先报告配置错误。
- 置信度：100%。

#### I5. 全量测试保留一个版本前既有失败

- 问题描述：`HostE2E.WifiDisconnectReconnect` 在目标 WiFi中断后期望自动恢复，但当前状态机会耗尽重试、清除凭据并重新进入配网。这一失败已记录于 beta v1.0.0文档，和本次 DHCP启动修复无关。
- 自决方案：不修改该状态机产品语义；完整报告同时记录全量79/80和排除该既有项79/79。
- 自决理由：修复它会扩大需求至目标 WiFi断开后的凭据保留/自动重连策略，违反当前范围。
- 风险预警：阶段四整体验收仍需明确列出该既有失败，不能写成全量全绿。
- 置信度：100%。
