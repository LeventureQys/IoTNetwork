### 自决区（不阻塞阶段流）

#### D1. 自定义 prefix 与固定备用网段如何组合

- 问题描述：阶段一确认的四个候选均是 `/24`，同时配置增加 `prefix_length` 以消除代码写死掩码。若将候选直接套用任意 prefix，`10.42.0.1/16` 与 `10.43.0.1/16` 会成为同一网段。
- 自决方案：配置中的首选 AP 使用 `subnet/prefix_length`；默认首选为 `10.42.0.1/24`。自动备用候选固定为文档确认的三个 `/24`：`10.43.0.1/24`、`172.31.250.1/24`、`192.168.250.1/24`。DHCP 池按首选配置中的 host offset 重定位；候选容纳不下该 offset 时跳过。自定义非 `/24` 首选冲突后仍可回退固定 `/24` 候选。
- 自决理由：严格保持用户确认的候选地址契约，同时允许首选网段配置其他合法 prefix，避免候选重复或语义漂移。
- 风险预警：自定义大地址池可能无法重定位到 `/24` 备用段；此时应跳过候选并最终 fail-closed。
- 置信度：96%。

#### D2. 路由采集实现选择

- 问题描述：需求要求检查本机所有有效 IPv4 直连路由，解析 `ip route` 文本不稳定。
- 自决方案：使用 rtnetlink `RTM_GETROUTE`；仅把 `AF_INET`、`RTN_UNICAST`、存在输出接口、无 gateway、输出接口 UP 的路由作为直连冲突集合。路由查询失败、消息截断或容量不足均 fail-closed。
- 自决理由：netlink 是 Linux 内核结构化接口，不依赖命令输出语言和版本。
- 风险预警：需覆盖 main 之外的路由表，并对 `/0`、`/32` 做区间重叠测试。
- 置信度：94%。

#### D3. 系统命令执行方式

- 问题描述：当前 root 路径通过 `/bin/sh -c` 拼接配置字符串，存在转义、命令注入和错误归属困难。
- 自决方案：新增 argv 形式的进程执行辅助函数，通过 `fork/execvp` 启动 `iw`、`ip`、`hostapd`、`dnsmasq` 和 `iptables`；配置中的接口名、路径和 SSID仍需严格校验。只保留无外部输入的固定诊断命令使用场景，不再把配置值拼入 shell。
- 自决理由：配置文件在真实设备上由部署环境提供且进程以 root 运行，必须消除 shell 注入面。
- 风险预警：需要正确关闭继承 fd、等待子进程并保留退出码。
- 置信度：95%。

#### D4. 单实例锁生命周期

- 问题描述：真实模式共享 AP 接口、pidfile、TCP 5935 和工作目录，多实例会互相清理资源。
- 自决方案：在 `linux_hotspot_init()` 校验配置后，以 `<work_dir>/modu_linux_hotspot.lock` 获取非阻塞 `flock`，锁持有至 `linux_hotspot_deinit()`；lock 文件不删除。初始化失败通过 backend create 传播到设备入口并退出。
- 自决理由：进程锁比 pidfile 更能防止竞态和 PID 重用，且不影响模拟多实例。
- 风险预警：需新增 deinit 调用并覆盖异常退出后的锁释放。
- 置信度：94%。

#### D5. NAT 实现边界

- 问题描述：阶段一确认 NAT 默认关闭，但显式启用时需要完整所有权和清理。
- 自决方案：不创建额外链；使用一条带 comment `modu-provision-nat` 的精确规则：`POSTROUTING -s <final-cidr> -o <sta> -m comment --comment modu-provision-nat -j MASQUERADE`。添加前 `-C`，停止时循环删除完全相同规则。要求 `ip_forward=1`，程序不自行修改。
- 自决理由：单条规则足以表达本版本 NAT 能力，避免专用链带来的并发和清理复杂度；规则所有权由完整参数和 comment 共同确定。
- 风险预警：部署防火墙 FORWARD 默认 DROP 时 NAT 仍不可用；因为 NAT 非配网必需能力，启用方需自行满足部署规则。
- 置信度：93%。
