# beta v1.0.3 设备端流程差异

- 对象：设备端状态机与设备网络抽象调用
- 当前验证平台：Linux
- 后续目标平台：ESP32-C3

## 1. 设备端计划流程

```text
AP_PROVISION
  -> 收到 wifi_config
  -> 连接目标 WiFi
  -> 校验 SSID 和 IP
  -> 保存未确认凭据
  -> 发送 wifi_result ok
  -> 关闭 SoftAP
  -> DISCOVERY
  -> UDP 接收 host_announce
  -> CONNECT
  -> SESSION
```

## 2. 当前已实现

- SoftAP 和配网 TCP 服务。
- auth、wifi_config、wifi_result 协议处理。
- 目标 WiFi 连接。
- 实际 SSID 和 IP 校验。
- 未确认凭据保存。
- discovery、connect、session 状态代码。
- UDP `host_announce` 解析。
- TCP `device_hello`、`host_ack` 和 ping/pong。

## 3. 当前缺口

### D1. `close_ap` 是唯一迁移条件

当前 `wifi_config` 成功只设置 `provision_wifi_ok=1`。设备必须收到 PC 的 `close_ap`，调用 `prov_server_stop()` 后，状态机才会进入 discovery。

相关代码：

- `demo/device/device_provision.c:295`
- `demo/device/device_provision.c:309`
- `demo/device/device_app.c:643`
- `demo/device/device_app.c:658`

最新真实日志没有 `RX close_ap`，所以设备没有进入 UDP 发现。

### D2. 成功后仍触发错误超时

当前超时判断没有排除 `provision_wifi_ok=1`。因此已经处理完 wifi_config 后，仍会打印“等待 wifi_config 超时”。

相关代码：`demo/device/device_provision.c:94-100`。

### D3. discovery 启动可观测性不足

`discovery_start()` 创建组播 socket，但成功时没有明确记录“UDP 组播监听已启动”。真实联调时无法只看日志确认 UDP 是否启动。

相关代码：`demo/device/device_discovery.c:10-24`。

## 4. 本版本设备端修改范围

### 4.1 配网成功后增加自动交接

推荐保持当前状态枚举不变，避免为了小修复增加复杂状态。

在设备结构体中增加一个简单的交接截止时间，例如：

```text
provision_handoff_deadline_ms
```

行为：

1. `wifi_result ok` 成功发送后设置短宽限期。
2. 宽限期内如果收到 `close_ap`，立即停止热点。
3. 宽限期到期仍未收到 `close_ap`，设备主动停止热点。
4. 状态机检测到热点已停止且 `provision_wifi_ok=1` 后进入 discovery。
5. 自动交接前再次确认 STA 仍连接目标 SSID并有 IP。

宽限期只用于给 PC 留出发送 `close_ap` 的机会，不承担 WiFi 重连职责。建议使用一个固定且较短的配置值，设计阶段再确定具体默认值。

### 4.2 修正超时条件和日志

- 只有 `provision_wifi_ok=0` 时才允许打印“等待 wifi_config 超时”。
- 成功后进入交接等待时，日志改为“等待 close_ap 或自动关闭热点”。
- 自动关闭时记录“未收到 close_ap，设备主动完成配网交接”。

### 4.3 增加 UDP 启动日志

`discovery_start()` 成功加入组播后记录：

```text
服务发现：UDP 组播监听已启动，地址=224.0.2.1:5936
```

加入失败时保留现有告警和候选地址回退行为。

## 5. ESP32-C3 迁移约束

设备状态机不能直接调用：

- `nmcli`
- NetworkManager
- Linux 网卡名
- Linux socket 专属接口

状态机只能通过现有 `net_abstraction` 调用：

- `net_wifi_sta_connect()`
- `net_wifi_get_ip()`
- `net_wifi_get_current_ssid()`
- `net_wifi_ap_stop()`
- `net_udp_mcast_join()`
- `net_udp_recv()`
- `net_tcp_connect()`

这样迁移到 ESP32-C3 时，只需要补齐或调整 ESP-IDF 网络后端，不需要重写配网状态机。

## 6. 设备端测试

### 正常路径

- 收到 wifi_config，目标 WiFi 成功。
- 收到 close_ap。
- 设备进入 discovery。

### 必须新增的异常路径

- wifi_result ok 后不发送 close_ap。
- 宽限期到期后设备自动停止 AP 并进入 discovery。
- wifi_config 失败时不得自动进入 discovery。
- 自动关闭前 STA 校验失败时不得进入 discovery。
- 重复 close_ap 不崩溃、不重复破坏状态。

## 7. 设备端完成标准

- `close_ap` 丢失不再阻断流程。
- 错误的“等待 wifi_config 超时”日志消失。
- 日志明确显示 AP 停止、discovery 和 UDP 启动。
- 模拟测试通过。
- Linux 真实稳定 WiFi 环境能继续进入 TCP 会话。
- 修改不引入 Linux 专属状态机逻辑，保持 ESP32-C3 可迁移性。
