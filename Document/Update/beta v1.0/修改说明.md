# PC 端 SERIAL_BYTES 数据面接收改造说明（provision_pc v1.0.5 → v1.0.6）

- 日期：2026-08-20
- 适用仓库：IoTNetwork `demo/pc`
- 变更性质：新增数据面消费链路，不修改 wire v2 协议与设备端行为

---

## 1. 背景与问题定位

### 1.1 现象

设备端（ESP32-C3）把外部 MCU 通过 UART1 上传的串口数据，以 wire v2 `SERIAL_BYTES` 帧转发给上位机后：

- 上位机能正常显示 `app_data` 调试消息（如 "12345_ESP32"）
- 上位机**看不到任何串口数据**，且无报错

### 1.2 根因（代码证据链）

`SERIAL_BYTES` 帧在上位机的唯一出路是数据面回调 `IHostDataSink::OnSerialBytes`，但该接口**全工程没有任何实现类，也从未被接线**：

| 位置 | 内容 |
|---|---|
| `demo/pc/core/host_tcp_server.cpp:582` | `if (sink_) sink_->OnSerialBytes(...)` —— sink 为空则静默丢弃 |
| `demo/pc/core/host_data_sink.h` | 定义 `IHostDataSink`（OnSessionOnline / OnSerialBytes / OnSessionOffline 三个纯虚接口），全工程搜索**零实现类** |
| `demo/pc/core/host_app.cpp:29` | `tcp_server_(net, registry_, params)` —— 构造未传 sink（默认 `nullptr`），且无任何地方调用 `SetDataSink()` |
| `demo/pc/ui/host_window.h` | 不继承 `IHostDataSink`，UI 目录无 serial 相关代码 |

对照：`app_data` 调试消息走 `LOG_I("HOST", "收到来自 %s 的调试消息：%s", ...)`（`host_tcp_server.cpp:635`），进入日志通道由 UI 日志模型显示，因此"只有调试信息"。

> 结论：**设备端转发功能正常**，问题在上位机数据面消费链路缺失（wire v2 数据面在上位机侧尚未落地）。

---

## 2. 修改目标

1. 上位机完整消费设备转发的 `SERIAL_BYTES` 帧
2. **落盘二进制文件为主渠道**（MCU 速率约 50KB/s，UI 实时显示意义不大），按 hello 携带的 `serial_profile.frame_size`（当前 3172）切帧
3. UI 显示接收统计（总字节数 / 帧数 / 最近一次接收时间），便于人工确认
4. 断线重连自动新建落盘文件，文件命名含设备 ID 与时间戳
5. 不影响现有 app_data 调试消息、心跳、设备表等功能

---

## 3. 修改前后数据流

**修改前**：

```
设备 --wire v2 SERIAL_BYTES--> HostTcpServer::HandleOnline 解析成功
                                     │
                                     └─ sink_ == nullptr → 静默丢弃
```

**修改后**：

```
设备 --wire v2 SERIAL_BYTES--> HostTcpServer::HandleOnline
                                     │  host 线程
                                     ▼
                        IHostDataSink::OnSerialBytes
                                     │
                                     ▼
        SerialDataModel（QMutex 保护的待处理队列 + 落盘文件）
                                     │  UI 线程 QTimer(150ms) Drain
                                     ▼
                    字节统计刷新 + 落盘缓冲刷盘
```

## 4. 修改点清单（6 处）

### 4.1 新增 `demo/pc/ui/components/serial_data_model.h/.cpp`

实现 `IHostDataSink`（不依赖 Qt 对象模型也可，但复用现有 `LogModel` 的"任意线程入队、GUI 线程 Drain"模式）：

```cpp
// serial_data_model.h 要点
#include "host_data_sink.h"
#include <QMutex>
#include <cstdio>
#include <vector>

class SerialDataModel : public IHostDataSink {
public:
    void OnSessionOnline(const std::string &device_id,
                         const std::string &session_id,
                         const HostSerialProfile &profile) override;
    void OnSerialBytes(const std::string &device_id,
                       const std::string &session_id,
                       const uint8_t *bytes, size_t length,
                       uint64_t receive_time_ms) override;
    void OnSessionOffline(const std::string &device_id,
                          const std::string &session_id,
                          const std::string &reason) override;
    void Drain();   /* GUI 线程定时调用 */
    /* 统计读取：总字节/帧数/最近接收时间/落盘路径 */
private:
    QMutex mu_;
    HostSerialProfile profile_;       /* OnSessionOnline 记录 */
    std::string device_id_;
    std::string session_id_;
    FILE *file_ = nullptr;            /* 落盘文件（OnSessionOnline 打开，OnSessionOffline 关闭） */
    std::string file_path_;
    uint64_t total_bytes_ = 0;
    uint64_t frame_count_ = 0;        /* 按 profile_.frame_size 切帧计数 */
    uint64_t last_rx_ms_ = 0;
    uint64_t dropped_bytes_ = 0;      /* 文件不可写等异常时计数 */
    std::vector<uint8_t> tail_;       /* 跨回调残留的不足一帧字节 */
};
```

实现要点：

- `OnSerialBytes`（**host 线程回调**）：仅做两件事——`fwrite` 追加到落盘文件；按 `profile_.frame_size` 切帧并更新统计。残留字节放 `tail_`，与下一次数据拼接。
- 接口注释约束（`host_data_sink.h`）：回调内不得持有 queue/registry 锁、不得销毁 host；本类仅碰自己的锁与文件，满足该约束。
- `OnSessionOnline`：记录 profile；打开新文件，路径形如 `logs/serial_<device_id>_<YYYYmmdd_HHMMSS>.bin`。
- `OnSessionOffline`：`fflush`/`fclose` 落盘文件，统计保留（UI 可继续显示最后值）。
- `Drain()`：GUI 线程调用，仅刷新统计展示，不做重活。

### 4.2 修改 `demo/pc/core/host_app.h` / `host_app.cpp`

把数据面 sink 透传给内部的 `tcp_server_`：

```cpp
// host_app.h
#include "host_data_sink.h"
// ...
void SetDataSink(IHostDataSink *sink) { tcp_server_.SetDataSink(sink); }

// host_app.cpp 无需其他改动（HostTcpServer 已有 SetDataSink 与空指针保护）
```

### 4.3 修改 `demo/pc/ui/host_window.h` / `host_window.cpp`

- `HostWindow` 增加成员 `SerialDataModel *serial_model_`（不要求 HostWindow 本身继承接口，持有模型即可，减少 Qt 多继承复杂度）
- 构造函数中创建 `serial_model_ = new SerialDataModel(this);`
- 界面增加一个统计标签（如 `QLabel *serial_stats_`），放在 `summary_` 附近；`Refresh()`（150ms 定时器已有）里调用 `serial_model_->Drain()` 并刷新标签文本：
  `串口数据：已接收 X 字节 / Y 帧，最近接收 HH:MM:SS，文件：<path>`（文件不可用时显示"落盘不可用，丢弃 Z 字节"）

### 4.4 修改 `demo/pc/app/main.cpp`

在 `HostWindow window(host);` 创建后接线，并在窗口析构前反注册：

```cpp
HostWindow window(host);
host->SetDataSink(window.serial_model());   // HostWindow 新增访问器
...
// window 随作用域结束析构；HostWindow 析构中：
// host_->SetDataSink(nullptr);
```

顺序约束：`host` 在 `window` 之后销毁（当前 main.cpp 顺序已满足），且 `HostWindow` 析构函数中必须先 `host_->SetDataSink(nullptr)` 再释放 `serial_model_`，防止 host 线程回调悬空指针。

- `pc_ui` 源文件列表增加 `ui/components/serial_data_model.cpp`
- 版本号：`project(ModuTechPc VERSION 1.0.6 LANGUAGES C CXX)`（manifest 自动携带新版本号）

## 5. 线程模型说明

| 线程 | 职责 |
|---|---|
| host 线程（`HostApp::Run`） | 收包解析 → `OnSerialBytes`（写文件 + 更新统计，全程短临界区） |
| GUI 线程 | 150ms `Refresh` → `SerialDataModel::Drain` → 刷新统计标签 |

- 数据入队/写文件与 UI 展示完全解耦，UI 不会成为接收瓶颈（落盘吞吐不受 UI 卡顿影响）
- 落盘文件写入失败时仅计数丢弃，不影响会话与心跳

## 6. 验证步骤

前置：设备侧固件（ESP32-C3-IoTNetwork，已实现 UART1 → SERIAL_BYTES 转发）烧录运行，MCU 接 UART1。

1. 上位机启动 → 设备上线 → 上位机自动发"启动上传"命令，MCU 开始上传
2. 上位机界面串口统计标签字节数持续增长，帧数 ≈ 字节数 / 3172
3. `logs/serial_*.bin` 文件生成且大小持续增长；用十六进制工具按 3172 字节切分可解析出完整帧
4. 断线（关热点）→ 上位机发"停止上传"→ 落盘文件自动关闭；重连 → 自动新建文件
5. 回归项：
   - app_data 调试消息（如设备每 10s 的 "12345_ESP32"）仍正常显示
   - 心跳 ping/pong 正常，无"pong 序号不匹配"告警恶化（上位机消费数据后事件循环不再被拖慢）
   - 设备侧日志不再出现"MCU 数据入队失败"（上位机消费正常后 TCP 排水恢复）
