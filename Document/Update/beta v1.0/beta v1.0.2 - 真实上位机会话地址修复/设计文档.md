设备发现上位机 `192.168.1.191:5935` 后，`demo/net_sim/sim_backend.cpp` 最终无条件连接 `127.0.0.1`。Windows 上位机 listener 已确认绑定 `0.0.0.0:<host_tcp_port>`；PC 端主要缺口是 listener 启动晚于通告组件、失败回滚不足、监听日志误写成通告 IP，以及通告地址过滤不足。

## 3. 双工作线

### 3.1 设备端工作线

负责：

- Linux 真实设备 TCP 连接使用发现端点。
- 保持模拟 AP、模拟 Host 和普通 loopback 行为。
- 请求目标/实际目标诊断日志。
- 设备日志文件落盘。
- Linux 设备构建、单元测试和启动冒烟。

不负责：

- PC listener、组播通告或 Windows 地址选择。
- 真实 mDNS。
- Windows 构建。

### 3.2 PC 端工作线

负责：

- listener 先于组播通告启动。
- 启动失败立即回滚 listener/announcer/mDNS状态。
- 监听端点和通告端点日志分离。
- 通告地址拒绝 unspecified、loopback 和 APIPA。
- Windows 专有源码的静态正确性与后续 Windows 验收说明。

不负责：

- 设备 `TcpConnect()`。
- 设备日志落盘。
- 实现真实 Windows mDNS。
- 多网卡最优路由和网络变化通知。

1. 设备端阶段三：只实施设备端计划并提交 Linux 测试结果。

## 5. 跨端接口契约

### 5.1 服务端点

- 通告 JSON字段保持：`ip` 为 IPv4字符串，`tcp_port` 为主机序 JSON整数。
- 设备解析后存入 `net_addr_t`：`ip`、`port` 均为网络字节序。
- PC真实 listener：`0.0.0.0:<host_tcp_port>`。
- PC通告端点：`<host_virtual_ip>:<host_tcp_port>`。
- 设备真实 effective 端点必须等于通告端点。

### 5.2 建连与会话

```text
PC listener ready
  -> PC announcer ready
  -> host_announce(ip, tcp_port)
  -> device sess_host = announce endpoint
  -> device TCP connect effective endpoint = sess_host
  -> device_hello
  -> host_ack status=ok
  -> ping/pong
```

协议字段、帧前缀和版本号均不变。

### 5.3 错误处理

- 设备连接失败：关闭本次 socket，返回现有 `DEMO_ERR*`，状态机进入 HEAL。
- PC listener 失败：`HostApp::Start()` 返回失败，不启动 announcer。
- PC announcer 失败：关闭 listener，`HostApp::Start()` 返回失败。
- PC mDNS兼容注册失败：记录警告，组播主路径可继续。

## 6. 不覆盖

- Windows真实 mDNS/DNS-SD。
- 多网卡路由 metric、WLAN GUID绑定和自动重通告。
- IPv6。
- 防火墙自动修改。
- Linux WiFi掉线根因。
- ESP32-C2后端。
