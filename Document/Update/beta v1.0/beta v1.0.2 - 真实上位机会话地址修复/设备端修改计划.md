# beta v1.0.2 设备端修改计划

## 1. 目标

仅修改设备端及设备使用的共用模拟后端，使 Linux 真实设备连接服务发现返回的真实上位机地址；同时保留全部模拟地址翻译，并让设备运行日志持久化。该计划可在当前 Linux 环境独立开发和验证，不依赖 PC 端代码完成。

## 2. 当前代码事实

- `demo/include/net_abstraction.h` 规定 `net_addr_t.ip`、`net_addr_t.port` 为网络字节序。
- `demo/device/device_session.c:14` 将发现得到的 host 原样传给 `net_tcp_connect()`。
- `demo/net_sim/sim_backend.cpp:545` 的 `TcpConnect()` 负责设备 Linux socket和模拟 socket。
- `demo/net_sim/sim_backend.cpp:568` 当前无条件使用 `INADDR_LOOPBACK`。
- `demo/tests/test_sim_socket.cpp` 已覆盖普通 loopback、模拟 AP、模拟 Host和连接拒绝，但没有覆盖真实目标保持。
- `demo/device/app/main.cpp` 只调用 `log_init()`，未调用 `log_set_file()`。

## 3. Stage D1：TCP地址修复

### 3.1 内部地址解析契约

在 `demo/net_sim/` 增加内部 helper，建议文件：

```text
demo/net_sim/sim_tcp_endpoint.h
demo/net_sim/sim_tcp_endpoint.cpp
```

建议接口：

```cpp
struct sim_tcp_endpoint_t {
    uint32_t ip;    // 网络字节序
    uint16_t port;  // 网络字节序
};

sim_tcp_endpoint_t sim_tcp_resolve_endpoint(
    bool real_device_mode,
    const net_addr_t &requested,
    bool simulated_ap_match,
    uint16_t simulated_ap_real_port_host_order,
    uint32_t simulated_host_ip_network_order,
    uint16_t simulated_host_port_host_order);
```

如果实现者能在不暴露 `sockaddr_in` 和平台头文件的情况下使用更小接口，可调整命名，但必须满足：

- 纯函数，无 socket、WiFi、SimWorld状态或系统调用。
- 输出字段均为网络字节序。
- 只供 `demo_sim_backend` 和测试使用，不进入公共网络抽象。

### 3.2 解析规则

优先级固定：

1. `real_device_mode=true`：输出等于 `requested`。
2. 模拟 AP命中：IP=`127.0.0.1`，端口=`htons(ap_real_port)`。
3. 请求 IP等于模拟 Host IP：IP=`127.0.0.1`，端口=`htons(host_tcp_port)`。
4. 其他模拟请求：IP=`127.0.0.1`，端口保持 `requested.port`。

Linux真实模式条件固定为：

```cpp
#ifdef __linux__
dev_index() >= 0 && params_.use_real_wifi_sta
#else
false
#endif
```

不得仅依据 `use_real_wifi_sta` 或目标网段判定。

### 3.3 TcpConnect接入

- 保持现有 socket创建、非阻塞、connect、select、`SO_ERROR`和关闭结构。
- helper只生成最终 IP/端口。
- 真实路径直接把网络序输出写入 `sockaddr_in`，不得再次转换。
- 所有失败返回前关闭 socket，`*sock` 只在成功时赋值。

### 3.4 诊断日志

至少记录：

```text
TCP连接：模式=<real|sim>，请求=<ip:port>，实际=<ip:port>
TCP连接失败：阶段=<immediate|wait|so_error>，实际=<ip:port>，错误码=<n>
TCP连接成功：实际=<ip:port>
```

地址打印使用 `inet_ntop()` 或跨平台等价实现；只转换副本用于展示。

## 4. Stage D2：设备日志落盘

### 4.1 主方案

只修改 `demo/device/app/main.cpp`，不在 `start_device.sh` 增加 tee。

在配置根目录成为当前目录后：

1. 创建 `logs/`。
2. 调用 `log_init(LOG_INFO)`。
3. 生成 `logs/provision_device_dev<index>_YYYYMMDD_HHMMSS.log`。
4. 调用 `log_set_file()`。
5. 成功时打印日志路径；失败时写 stderr但继续启动。
6. 所有正常清理完成后调用 `log_close_file()`。

时间转换沿用 PC 端的 `localtime_s/localtime_r` 跨平台分支。不得修改公共日志格式。

### 4.2 失败路径

- 配置解析和配置路径错误发生在日志初始化前，继续写 stderr。
- 日志目录或文件创建失败不应阻止网络程序启动。
- 后端、net ctx或device创建失败时，在返回前调用 `log_close_file()`。

## 5. Stage D3：设备端测试

### 5.1 单元测试

在 `demo/tests/test_sim_socket.cpp` 或独立相邻文件覆盖：

- 真实请求 `192.168.1.191:5935` 原样输出。
- 真实请求的 IP/端口网络序不被二次转换。
- 模拟 AP翻译到loopback和AP实际端口。
- 模拟 Host翻译到loopback和host端口。
- 普通模拟loopback行为保持。

现有 socket集成测试必须继续通过。

### 5.2 日志测试

如新增 `test_log.cpp`，加入现有 `provision_demo_tests`：

- 空路径返回 `DEMO_ERR_INVAL`。
- 唯一标记写入文件一次。
- sink启用后文件仍只写一次。
- 每例恢复 `log_set_sink(nullptr)` 并关闭文件。

设备日志命名和创建由启动冒烟验证，不要求为 `main()` 写单元测试。

### 5.3 Linux命令

```bash
cmake -S demo/device -B demo/build/device
cmake --build demo/build/device -j"$(nproc)"
cmake -S demo/tests -B demo/build_test
cmake --build demo/build_test -j"$(nproc)"
ctest --test-dir demo/build_test --output-on-failure
```

短时启动测试可使用 `demo/start_device.sh --duration 3`；该命令需要 sudo且会改变无线状态，执行前必须确认现场允许。若不允许，记录阻塞，不得伪造。
