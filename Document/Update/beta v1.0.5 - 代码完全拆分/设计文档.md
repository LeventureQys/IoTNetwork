# beta v1.0.5 代码完全拆分 - 设计文档

## 1. 背景与目标

当前 `demo/pc/` 和 `demo/device/` 虽有独立 CMake 入口，但均通过父目录共享生产源码、配置、模拟后端、UI 组件和第三方库，任一目录单独复制后无法构建或运行。本版本将其改造成两个完全自包含的产品目录，并将设备端 C++ 严格限制在 Qt UI 和最薄启动入口。

阶段一已确认：设备目录同时保留宿主 Qt 模拟器与 ESP32-C2 纯 C 移植骨架；允许独立 `demo/integration_tests/`，但其中不得包含或编译两端私有生产源码。需求和决策分别见 `需求文档.md` 与 `问题清单.md`。

## 2. 当前代码状态

### 2.1 父目录源码耦合

- PC 通过 `demo/pc/CMakeLists.txt:10` 定义 `DEMO_ROOT=..`，并从父目录引入 `cmake/`、`include/`、`net_sim/`、`net_win/`、`shared_ui/` 和 `third_party/`。
- 设备通过 `demo/device/CMakeLists.txt:10` 使用相同方式引入 `common/`、`include/`、`net_sim/`、`shared_ui/` 和 cJSON。
- `demo/cmake/DemoShared.cmake:33` 把公共 C 和 cJSON编成 `demo_common`；`demo/cmake/DemoShared.cmake:51` 把 C++ 模拟后端编成 `demo_sim_backend`。
- Linux 条件下，`demo/cmake/DemoShared.cmake:41` 会让 PC 和设备都编译设备热点与 STA 实现，职责错误。

### 2.2 设备端语言边界不满足

- `demo/device/app/main.cpp:53` 同时处理配置、路径、日志、NVS、后端、线程、信号和 Qt 生命周期，不是最薄 UI 启动入口。
- `demo/net_sim/sim_backend.cpp`、`sim_world.cpp`、`sim_tcp_endpoint.cpp` 是设备非 UI 基础设施，但使用 C++。
- `demo/device/ui/device_window.cpp:144` 直接操作网络抽象，`demo/device/ui/device_window.cpp:152` 直接调用设备业务对象，UI 与核心边界不清。
- `demo/device/device_app.h:22` 将跨线程快照描述为“原子字段读取”，但字段不是 C11 atomic；当前 UI 发送槽也存在覆盖和数据竞争风险。

### 2.3 测试与运行资源耦合

- `demo/tests/CMakeLists.txt:16` 和 `:32` 同时重新编译设备与 PC 私有核心；`demo/tests/test_host_app.cpp:11` 同时包含双方私有头。
- PC 默认从工作目录读取 `config/demo_config.json`，见 `demo/pc/app/main.cpp:29`。
- 设备会向上搜索配置并修改进程工作目录，见 `demo/device/app/main.cpp:32` 和 `:84`。
- 两端共享 `demo/config/demo_config.json`，其中混合 PC、设备、模拟和 Linux 热点字段。

## 3. 设计原则

1. **产品自包含**：`demo/pc/` 与 `demo/device/` 各自拥有构建、源码、配置、第三方、测试、脚本和 README。
2. **无源码跨端依赖**：任何一端不得引用另一端或根级旧共享生产目录。
3. **设备非 UI 纯 C**：设备 `src/`、`backends/`、`firmware/` 仅允许 C11；C++ 仅存在于 `app/qt_main.cpp` 和 `ui/`。
4. **协议行为冻结**：目录和语言重构不得改变协议、状态值、错误码、NVS 键和流程语义。
5. **测试按所有权拆分**：端侧白盒测试归端侧；跨端测试只消费可执行产物和公开契约。
6. **显式运行路径**：配置、日志、NVS、模拟目录均由配置文件位置或命令行确定，不依赖当前工作目录。
7. **先复制验证，后删除旧根目录**：在两端独立构建和测试通过前不删除旧共享源码。

## 7. PC 端设计

### 7.1 构建目标

- `pc_cjson`：PC 私有 cJSON。
- `pc_common`：C11，包含 frame/log/net abstraction/params/protocol。
- `pc_socket_backend`：TCP、UDP、非阻塞 socket、时钟和随机数，不含 WiFi/AP/NVS/SimWorld。
- `pc_sim_backend`：PC 模拟 WiFi、AP catalog 读取、模拟地址转换和故障支持。
- `pc_win_backend`：Windows Native WiFi 与真实 socket；不得链接 `pc_sim_backend`。
- `pc_core`：现有六个 `host_*` 模块，只依赖抽象层。
- `pc_ui`：Qt 窗口和 PC 自有 UI 组件。
- `provision_pc`：公开宿主可执行产物。
- `pc_*_tests`：PC 自有单元/组件测试。

所有选项和警告使用目标级 CMake；禁止 `DEMO_ROOT`、指向 PC 根外的 `add_subdirectory`、源码和 include 路径。Windows 显式链接 `wlanapi`、`iphlpapi`、`ws2_32`；Linux PC 本版本仅承诺 sim，不编译设备热点代码。

### 7.2 Windows 后端拆分

当前 `demo/net_win/win_backend.cpp:2` 包含 `sim_backend.h`，并在创建时内部创建模拟后端以复用 socket/NVS。新设计将 socket/UDP/time/random 抽到 PC 自有 `pc_socket_backend`，Windows 后端直接组合该目标，不创建 `SimWorld`，不发布 AP catalog，不持有设备 NVS。

### 7.3 PC 配置与路径

PC 配置仅保留上位机、协议、目标 WiFi、模拟 catalog 与日志字段。解析优先级：

1. `--config`；
2. `MODUTECH_PC_CONFIG`；
3. 可执行文件部署目录下 `config/pc_config.json`；
4. 均不存在则使用内置默认参数并打印警告，保持拆分前兼容行为。

配置内相对路径相对于配置文件目录解析。`--runtime-dir`、`--sim-catalog-dir`、`--log-dir` 可覆盖配置。程序不得向上搜索仓库，不得依赖 CWD。

## 8. 设备端纯 C 设计

### 8.1 语言边界

允许的生产 C++ 文件仅为：

- `device/app/qt_main.cpp`
- `device/ui/*.cpp` 与对应 Qt 头

`device/src/`、`device/backends/`、`device/firmware/` 不得出现 `.cpp`、Qt include、`std::`、`new/delete` 或 C++ class。CMake 依赖方向固定为：

```text
provision_device(Qt) -> device_ui(Qt) -> device_host_facade(C)
                                          -> device_runtime(C)
                                          -> device_core(C)
                                          -> selected_backend(C)
```

反向依赖禁止。UI 只能包含 `device_host.h`，不得包含 `device_app.h`、`device_priv.h`、`net_abstraction.h` 或具体后端头。

### 8.3 生命周期与错误处理

- `create`：按第 10 节兼容配置语义加载、解析路径，并依次创建队列/锁、后端、`net_ctx`、core；失败时 `*out_host=NULL` 且无残留。
- `start`：只允许 `CREATED -> RUNNING`；线程创建失败保持 CREATED。
- `request_stop`：线程安全、非阻塞、幂等。
- `join`：超时返回 `DEVICE_ERR_TIMEOUT`，句柄仍有效；成功后不再写快照或日志。
- `destroy`：接收二级指针并置 NULL；运行中返回 BUSY，不隐式永久阻塞；按 core、net ctx、backend、队列/锁、配置逆序释放。
- 所有错误通过返回码和 `device_error_t` 传递；C 层不得 `exit`、抛异常或弹 Qt 对话框。

### 8.4 命令、快照与日志并发

- UI 到设备线程使用固定容量 32 的 C 命令环形队列；满时返回 BUSY，不覆盖旧命令。
- `app_data` 提交时复制最多 512 UTF-8 字节；非会话态返回 INVALID_STATE。
- 快照由 mutex 或 C11 atomic/seqlock 保护，一次复制完整 DTO。
- 日志使用 C 队列 pull 模式，UI 定时 drain；不得将 Qt 对象注册为全局 C sink。队列溢出累计 dropped 数量。
- signal handler 只设置安全停止标志/事件，不调用日志、malloc、Qt、网络或销毁。

### 8.5 模拟后端纯 C 化

现有 C++ 单体拆为 `sim_backend.c`、`sim_world.c`、`sim_socket.c`、`sim_tcp_endpoint.c`、`sim_nvs.c`、`sim_ap_catalog.c`、`sim_mdns.c`、`sim_fault.c`、`sim_random.c`。所有状态进入显式 `sim_backend_t`/`sim_world_t`，禁止 singleton/class/std::filesystem/std::thread。

模拟 AP catalog 是双进程公开运行契约：integration 向两端传入同一个绝对 `sim_catalog_dir`。设备发布 AP endpoint JSON，PC 读取；目录不得从 `nvs_dir` 或 CWD 隐式推导。

AP catalog 文件契约在本设计冻结，SS02 与 SS04 共同实现：

- 文件名：`device-<device_index>.json`，索引十进制 0～15。
- 写入：设备在同目录写 `device-<index>.json.tmp-<pid>`，flush 后原子替换正式文件；停止 AP 和正常退出时删除正式文件及本进程临时文件。
- JSON schema：

```json
{
  "schema": 1,
  "device_index": 0,
  "device_id": "02:00:00:00:00:01",
  "ssid": "Modu_0001",
  "bssid": "02:00:00:00:00:01",
  "logical_ip": "192.168.1.1",
  "loopback_host": "127.0.0.1",
  "provision_port": 15935,
  "published_at_ms": 0,
  "owner_pid": 1234
}
```

- 所有字段必需且类型严格；未知字段忽略。schema 非 1、索引/端口越界、IP 非法或 JSON 损坏的记录被 PC 忽略并警告。
- PC 每次扫描重新读取目录；同一索引仅使用正式文件。记录超过 30 秒且 `owner_pid` 已不存在时视为过期并忽略；无法判断 PID 是否存在时仅使用 30 秒时效。
- PC 不删除设备正式文件；integration 每场景使用独立空目录并负责场景结束后的目录清理。

### 8.6 Linux 与 ESP32

- Linux 热点/STA 全部归设备，改为实例上下文；不得使用进程级 `g_cfg/g_runtime/g_sta_iface`。
- Linux 真实后端失败必须 fail-closed，不回退 sim；fake ops 测试无需 root，真实热点验收单独执行。
- `nmcli` 等命令通过 argv + exec 调用，不拼 shell 命令；不得记录密码。
- ESP32 文件归入 `device/backends/esp32c2/`，并建立 `device/firmware/esp32c2/` ESP-IDF 工程。未实现能力明确返回 NOT_SUPPORTED；README 区分可编译骨架与实机功能。

## 9. `net_ctx` 创建契约修正

当前 `demo/common/net_abstraction.c:18` 忽略 backend init 返回值。本版本两端副本统一改为：

```c
int net_ctx_create(const net_backend_t *backend,
                   void *backend_user,
                   const char *config_path,
                   net_ctx_t **out_ctx);
```

- 进入函数先置 `*out_ctx=NULL`。
- backend 或 out_ctx 为空返回 `DEMO_ERR_INVAL`。为保持现有抽象语义，除生命周期外的能力回调允许为空，由 `net_xxx` wrapper 安全返回 `DEMO_ERR`；不额外定义“必需能力回调”。
- init 为空视为无需初始化；init 非空且失败时释放 ctx 并返回原错误。
- 仅 init 成功后标记 initialized；destroy 只对已初始化后端调用 deinit。
- backend_user 的所有权仍归具体 backend wrapper，不由 `net_ctx_destroy` 释放。

该修正保持其余 29 个抽象操作的行为语义不变。

## 10. 配置契约

PC 与设备分别使用 `pc_config.json`、`device_sim.json`、`device_linux.json`；共同协议字段必须同值。为避免目录重构改变既有配置兼容行为，保留现有“缺失文件使用内置默认值、未知或类型不匹配字段忽略、过长字符串按目标容量截断”的语义，并打印警告。路径处理统一要求：

1. `--config` 未指定时使用端侧部署默认路径；文件缺失继续使用内置默认参数并打印警告。
2. CLI 相对路径以进程启动 CWD 解析并立即规范化为绝对路径；配置文件内部相对路径以配置文件目录解析。
3. integration 一律传绝对 `runtime_dir`、`sim_catalog_dir`、`log_dir`、`events_jsonl_path` 和 `scenario_path`。
4. 保持现有字段容错与截断行为；新增端侧路径字段采用相同容错原则。
5. `device_index` 的 CLI 范围继续严格限制为 0～15；已有业务参数范围语义不改变。
6. 不调用 `chdir`，不向上搜索仓库。
7. 密码不得写入日志；仓库模板只使用演示凭据。

## 11. 结构化集成事件契约

两端可选 `--events-jsonl <path>`。CLI 相对路径按第 10 节规范化；integration 必须传绝对路径。每行独立 JSON：

```json
{"schema":1,"seq":1,"time_ms":0,"role":"pc","event":"ready","device_id":"","result":"ok","code":0,"data":{}}
```

必需字段：`schema`、`seq`、`time_ms`、`role`、`event`、`result`、`code`、`data`；设备相关事件增加 `device_id`。写入必须按行完整 flush；事件文件不可写时，显式指定该参数的进程必须启动失败。

最小事件集合：`ready`、`ap_ready`、`auth_result`、`wifi_result`、`close_ap_sent`、`session_online`、`session_offline`、`ping`、`pong`、`app_data_tx`、`app_data_rx`、`fault_applied`、`host_bye_sent`、`shutdown_complete`、`error`。

事件的稳定 `data` 契约如下；未列出的附加字段允许存在，但断言方必须忽略：

| event | role | 触发时机 | data 必需字段 |
|---|---|---|---|
| `ready` | 两端 | 后端、监听和事件写入器初始化完成 | `backend:string`, `pid:number` |
| `ap_ready` | device | 配网 AP 已可连接 | `ssid:string`, `endpoint:string` |
| `auth_result` | 两端 | auth 收发完成 | `status:"ok"|"fail"` |
| `wifi_result` | 两端 | wifi_result 收发完成 | `status:"ok"|"fail"`, `reason:number` |
| `close_ap_sent` | pc | close_ap 发送尝试结束 | `send_result:number` |
| `session_online` | 两端 | hello/ack 后会话上线 | `peer:string`, `reconnect_count:number` |
| `session_offline` | 两端 | 已上线会话断开 | `reason:string` |
| `ping`/`pong` | 两端 | 对应帧发送或接收 | `direction:"tx"|"rx"`, `sequence:number` |
| `app_data_tx`/`app_data_rx` | 两端 | app_data 成功发送/接收 | `text_bytes:number`, `sha256:string` |
| `fault_applied` | 两端 | scenario 故障动作生效 | `action:string`, `status:"ok"|"fail"` |
| `host_bye_sent` | pc | host_bye 写入完成 | `send_result:number` |
| `shutdown_complete` | 两端 | 工作线程 join 且资源释放完毕 | `exit_code:number` |
| `scenario_result` | 两端 | 目标 action 执行或拒绝后 | `action_id:string`, `action:string`, `status:"ok"|"rejected"|"failed"`, `request_bytes:number`, `reason:string` |
| `error` | 两端 | 非 scenario 的可观察错误发生 | `operation:string`, `message:string` |

顶层 `result` 只能为 `ok` 或 `fail`；`code` 为稳定端侧错误码或底层 `DEMO_*` 映射。每个进程的 `seq` 从 1 单调递增。`shutdown_complete` 必须是该进程最后一个事件。

`--scenario <path>` 只允许 sim 后端，文件 schema 固定为：

```json
{
  "schema": 1,
  "actions": [
    {
      "id": "unique-id",
      "target": "pc|device",
      "after_event": "ready|ap_ready|session_online|session_offline|null",
      "delay_ms": 0,
      "action": "auto_provision|send_app_data|inject_fault|request_stop",
      "args": {}
    }
  ]
}
```

`id` 在文件内唯一，`delay_ms` 范围 0～60000。`auto_provision.args` 需要 `ssid`、`password`；`send_app_data.args` 需要 `text`；`inject_fault.args` 需要 `name`、可选 `argument_json`；`request_stop.args` 必须为空对象。目标不匹配当前进程的 action 被忽略；目标匹配但 action、args 或 schema 非法时启动失败。一个 action 只执行一次，并且必须恰好产生一条同 `action_id` 的 `scenario_result`。512 字节合法发送产生 `status=ok` 后还应出现 app_data tx/rx；513 字节拒绝产生 `status=rejected`、`request_bytes=513`、`reason=payload_too_large`，且不得出现对应 tx。正式运行不传参数时不创建事件/场景通道。

## 13. 构建和发布契约

两端 CMake 都提供 `*_BUILD_TESTS`、`*_WARNINGS_AS_ERRORS`、模拟后端开关；Qt AUTOMOC 仅用于 UI 目标。两端定义标准 CMake install 规则，使用 `cmake --install <build> --prefix <artifact>` 生成：

```text
artifact/
├── bin/provision_<pc|device>[.exe]
├── config/
├── share/protocol-contract.json
└── manifest.json
```

`manifest.json` 至少记录产品、版本、平台、构建类型、Git revision 和可执行相对路径。integration 记录 artifact SHA-256。

## 14. 失败处理

- 迁移阶段任一端无法独立构建：停止删除旧共享目录，修复该端。
- 协议 manifest 不一致：失败，不通过复制覆盖或忽略差异。
- 设备非 UI C++ 扫描有命中：失败，定位到对应 SubStage 修复。
- integration 需要私有源码：失败，改为公开进程/事件契约。
- 真实平台环境缺失：在验收报告记阻塞；不得用 sim 代替真实项通过。
- 工具链存在但编译/启动失败：记失败，不得记阻塞。

## 15. 明确禁止事项

- 不改变线上协议、设备状态顺序、NVS 键和历史流程语义。

- 不用 symlink、junction、submodule 或构建时复制原根源码伪装自包含。
- 不让设备 C 目标以 C++ 编译器编译 `.c` 文件绕过语言门禁。
- 不在 integration 中包含端侧源码或私有头。
- 不宣称 ESP32 骨架已通过实机功能验收。
- 不删除或修改与本版本无关的用户工作区变更。
