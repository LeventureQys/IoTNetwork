### 自决区（不阻塞）

#### CQ1. Windows 现代移动热点 API 的编译可用性以 fail-closed 兜底
- 问题描述：SS2.1 要求只使用现代 Windows 10/11 移动热点/WinRT 能力（`开发文档/SubStage_SS2.1_PC热点与生命周期.md:48`），但当前 MSVC + Qt 工具链下具体 API 是否可编译、是否存在可用网卡驱动需开发中验证。
- 自决方案：开发中优先验证现代 API 编译；若编译受阻，SubAgent 必须停止并上报，由 MainAgent 评估替换实现（仍不得回退 deprecated hostednetwork）。运行时能力/权限/网卡缺失一律 fail-closed，不得静默降级。
- 自决理由：阶段一 Q4 与设计文档已固定该路线；编译/运行失败属实现细节，不影响路线。
- 风险预警：若工具链完全无法支持所选现代 API 且无替代现代路径，将影响 Windows 真实验收，需上报置顶。
- 置信度：95%

#### CQ2. 真实 Windows/Linux 无线环境的可用性决定启动测试状态
- 问题描述：阶段三需要真实 Windows 热点启动与 Linux STA 核心路径测试（`开发文档/SubStage_SS3.1_集成测试与文档.md:50`），依赖本机网卡、驱动、权限与跨机环境。
- 自决方案：先完成 sim 双进程与 offscreen 自动化；随后探测真实环境。若某真实环境缺失，将该验收项记录为阻塞并追加到本清单置顶区，写明具体依赖与已尝试命令，不以 sim 冒充通过。
- 自决理由：符合 `Document/Agent开发规范.md:180` 启动测试门禁与验收文档 DQ7 约定。
- 风险预警：若两个真实环境均缺失，Version 将在真实环境验收项阻塞，需用户提供环境或接受阻塞结论。
- 置信度：99%

#### CQ3. PC 端设计审查子代理未返回不影响开发
- 问题描述：阶段二 PC 端设计审查因超时未返回结论；设计已基于代码证据完成并定稿。
- 自决方案：不再等待该审查；SS2.1/SS2.2 开发过程中由 SubAgent 按任务书执行，若发现设计文档与代码冲突立即停止上报。
- 自决理由：任务书包含完整代码位置与契约，设计自检已通过，审查属增强而非前置。
- 风险预警：Windows 热点 API 细节可能在开发中被发现，按 CQ1 处理。
- 置信度：98%

## v2 追加（开发过程中，2026-08-03）

### 置顶区（待用户确认，阶段阻塞）

#### CQ4. Linux 真实后端核心路径无法在本机验证（Windows 开发机）
- 问题描述：设备端 Linux 真实后端（`--backend linux`）依赖 Linux 环境、nmcli、无线网卡与 PC 热点；本机为 Windows（MSVC 2022），`backends/linux/` 仅编译为 NOT_SUPPORTED stub，实测返回 DEVICE_ERR_NOT_SUPPORTED（非缺陷，属既定 fail-closed）。`tests/linux/test_linux_backend.cpp` 为 Linux-only，本机无法编译执行。SS2.3 已完成源码级解耦（`linux_wifi_create` 不再依赖 hotspot/root），但真实 STA 核心路径、普通用户创建后端、nmcli 连接 PC 热点等验收项均无法在本机执行。
- 建议方案：sim 自动化与单元测试作为本机可执行部分全部通过（设备 ctest 134/134）；Linux 真实验收项标注为阻塞，需在具备 nmcli/无线网卡/PC 热点的 Linux 环境（实机或 CI）执行；提供执行命令清单与预期证据模板，待环境就绪后补测。
- 备选方案：用户提供 Linux 环境（实机/虚拟机/CI）后由 MainAgent 追加一轮验收。
- 风险预警：若最终无 Linux 环境，Version 的「Linux 真实设备启动」（验收项 C5/D2A）将保持阻塞，不能判定 Version 完成，除非用户明确接受该阻塞结论。
- 置信度：99%
- 归入置顶原因：真实环境验收项无法执行，需要用户决策（提供环境或接受阻塞）。

#### CQ7. Windows 真实热点固定 IP 改写需管理员权限（WinRT 热点本身已实测启动成功）
- 问题描述：本机存在 Realtek 8821CE 无线网卡。SS3.1 实测 `provision_pc.exe --backend windows --duration 8`：WinRT 现代移动热点**启动成功**（日志「Windows 移动热点已启动，SSID=Modu_PC」）；但本机热点实际 IP=169.254.183.146/16（APIPA），触发固定 IP 改写分支，`SetUnicastIpAddressEntry` 返回错误码 5（ERROR_ACCESS_DENIED，权限不足）→ `hotspot_error` → 按设计 fail-closed 回滚（热点停止、退出码 2、不启动 TCP）。即：现代热点 API 与 fail-closed 行为均得到实证；唯一阻塞是固定 IP 改写需管理员权限。验收项 C4 部分通过（热点创建）、D2（固定 IP 修正）需管理员权限重跑。
- 建议方案：以管理员权限重跑 `provision_pc.exe --backend windows`（此时 SetUnicastIpAddressEntry 应成功，热点 IP 变为 192.168.137.1/24，TCP 5935 监听启动），补齐 C4 完整路径与 D2 证据；或用户明确接受「固定 IP 改写需管理员权限」为产品运行前提并在文档注明。
- 备选方案：产品文档把「以管理员身份运行」列为 PC 端部署要求（修改适配器 IP 属系统管理操作，本就需提升权限），验收时以管理员权限执行。
- 风险预警：若用户不接受管理员权限要求，则需重新设计固定 IP 策略（如依赖 ICS 默认网段，但本机实测为 APIPA，不可依赖）。
- 置信度：99%
- 归入置顶原因：真实 Windows 验收项（C4/D2）的剩余阻塞需用户决策（提供管理员权限环境或接受部署要求）。

### 自决区（不阻塞）

- 问题描述：SS2.3 已从 `device_core` 与测试源列表移除这两个旧模块，磁盘文件保留但无任何 CMake 引用。

#### CQ6. 旧 WiFi 故障注入 action 与 sim 旧底层原语的处理
- 问题描述：SS2.4 报告 sim 仍接受 `wifi_disconnect/wifi_ok/wifi_auth_fail/wifi_auth_ok` 注入（不影响 catalog 连接路径）；`sim_world` 保留旧 target 网络/AP 注册表原语（有独立单测）。
- 自决方案：保留（fail-closed 语义：不生效但不报错），不在本 Version 清理；集成测试不使用这些 action。`sim_world` 旧原语保留供底层单测。
- 自决理由：删除会扩大改动面且无业务收益；保留不影响 v1.1 主路径与验收。
- 风险预警：无。
- 置信度：95%
