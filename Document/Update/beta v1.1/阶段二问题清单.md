### 自决区（不阻塞）

#### DQ1. PC 热点能力应扩展现有网络后端契约，而不是绕过后端在 HostApp 中直接调用系统命令
- 问题描述：`demo/pc/include/pc/net_abstraction.h:20` 定义统一后端 vtable，现有 Windows 后端却将 `wifi_ap_start/wifi_ap_stop` 映射为不支持（`demo/pc/backends/windows/win_backend.cpp:298`、`demo/pc/backends/windows/win_backend.cpp:506`）。若在 `HostApp` 直接调用 WinRT 或系统命令，会破坏 sim/Windows 可替换性与单元测试边界。
- 自决方案：保留 `wifi_ap_start/wifi_ap_stop` 入口并补充热点 IP 校验/配置所需后端接口；Windows 真实后端实现系统托管热点，sim 实现确定性虚拟热点。`HostApp` 只编排接口，不包含平台 API。
- 自决理由：现有代码已采用后端抽象，延续该边界可独立测试错误路径并保证非 Windows 构建不引用 WinRT。
- 风险预警：扩展 vtable 时 PC socket/sim/windows fake 后端和测试夹具必须同步，否则会发生 ABI/初始化顺序错误。
- 置信度：97%

#### DQ2. Windows 热点实现应封装为独立组件，不继续膨胀 `win_backend.cpp`
- 问题描述：`demo/pc/backends/windows/win_backend.cpp:1` 已同时承担 Native WiFi、IP、网关和 socket 组合，新增 WinRT 移动热点、适配器地址和错误映射会显著增加职责。
- 自决方案：新增 `backends/windows/win_hotspot.h/.cpp`，公开 C++ 内部接口，由 `win_backend.cpp` vtable 适配；组件负责启动、停止、读取承载适配器 IPv4、配置 `192.168.137.1/24` 和错误文本。WinRT/系统依赖仅在 `pc_win_backend` 目标中链接。
- 自决理由：独立组件可用 fake system ops 做单元测试，避免平台代码污染 HostApp 和公共 C 契约。
- 风险预警：现代 Windows API 的具体可用性必须在阶段三编译环境验证；不可用时必须 fail-closed，禁止回退 deprecated hostednetwork。
- 置信度：94%

#### DQ3. 设备状态枚举应裁剪为六态并同步协议契约
- 问题描述：当前设备状态是 BOOT→STA_JOIN→AP_PROVISION→DISCOVERY→CONNECT→SESSION→HEAL（`demo/device/include/protocol.h:47`），UI 也固定展示七步（`demo/device/ui/flow_widget.cpp:7`）。v1.1 已删除 AP 配网和服务发现。
- 自决方案：状态调整为 `BOOT=0, WIFI_SCAN=1, STA_JOIN=2, CONNECT=3, SESSION=4, HEAL=5, COUNT=6`。设备先扫描并确认精确 SSID存在，再连接；连接失败或断线进入 HEAL，退避后回 WIFI_SCAN；TCP 失败在 HEAL 后重试固定地址。
- 自决理由：显式 WIFI_SCAN 能直接对应需求“主动扫描”，且删除两个无效状态后流程可观察、可测试。
- 风险预警：状态数值变化会影响 UI、事件、测试和协议 contract，必须由契约 SubStage 先统一修改。
- 置信度：96%

#### DQ4. 设备目标 WiFi 不写 NVS，使用只读启动配置
- 问题描述：当前设备通过 `wifi_creds` NVS 维护两组凭据与确认回滚（`demo/device/src/core/device_app.c:319`），但 v1.1 SSID/密码由配置约定，不再动态下发。
- 自决方案：使用 `device_config_t.pc_ap_ssid`、`pc_ap_password`、`pc_host_ip`、`host_tcp_port` 作为启动期只读配置；删除业务层凭据 NVS 读写、确认窗口和候选地址持久化，仅保留事件日志所需 NVS 能力。
- 自决理由：运行时不存在修改凭据入口，持久化会形成第二数据源并增加回滚状态。
- 风险预警：修改 SSID 必须同步 PC 和设备配置；配置校验失败应在启动时终止而非进入无限重试。
- 置信度：98%

#### DQ5. PC 一对一连接拒绝使用 `host_ack status=busy` 作为兼容错误帧
- 问题描述：阶段一决定去掉多设备业务和 `busy` 扩展，但 TCP 服务仍需要可观察地拒绝第二连接。现有服务会用 `host_ack busy` 后关闭（`demo/pc/core/host_tcp_server.cpp:120`）。
- 自决方案：协议 commands 继续只列 `host_ack`，其 `status` 保留 `ok|busy|fail` 错误语义；PC 固定容量为 1，第二个完成 `device_hello` 的连接收到 `{"cmd":"host_ack","status":"busy","reason":"single_device_only"}` 后关闭。删除可配置多连接上限和复杂注册表容量逻辑，但保留这一拒绝响应。
- 自决理由：无需新增命令即可提供确定性错误，设备现有会话层也已经识别 busy。
- 风险预警：阶段一 Q5 中“去掉 busy”应理解为删除多容量调度，而非让第二连接无响应关闭；该细化不改变路线。
- 置信度：92%

#### DQ6. sim 热点目录模型反转为 PC 发布、设备读取
- 问题描述：当前 sim catalog 由设备热点发布，PC 扫描并连接（`demo/device/backends/sim/sim_backend.c:188`；`demo/pc/core/host_provision_client.cpp:109`）。v1.1 需要 PC 创建热点、设备扫描连接。
- 自决方案：共享 sim catalog schema 升级为 PC 热点记录，字段至少含 `schema=2`、`ssid`、`password`、`logical_gateway=192.168.137.1`、`tcp_port=5935`、`loopback_host=127.0.0.1`、`loopback_port`、`owner_pid`、`published_at_ms`。PC sim 后端启动时发布并停止时删除；设备 sim 后端扫描/STA 连接读取记录，TCP 固定地址经记录翻译到 loopback。
- 自决理由：反转 catalog 所有权才能让双进程 sim 真实模拟新数据流，而不是通过测试捷径跳过扫描和热点启动。
- 风险预警：PC 与设备各自自包含，不能互相引用源码；schema、字段和校验逻辑需要两端各自实现，并由集成 golden 测试语义一致。
- 置信度：95%

#### DQ7. 阶段三完成必须提供真实环境阻塞判定而非默认通过
- 问题描述：Windows 热点与 Linux WiFi 均依赖真实无线网卡、权限和系统服务；当前工作机可能无法同时提供两个目标环境。
- 自决方案：自动化阶段必须通过双端单元测试、sim 双进程和 offscreen 启动。真实 Windows 热点启动与 Linux STA 核心路径分别执行；环境缺失时在阶段三问题清单置顶并记录具体依赖、命令和日志，不能用 sim 替代。阶段四只有阻塞解除后才能最终通过对应真实验收项。
- 自决理由：符合 `Document/Agent开发规范.md:180` 的启动测试门禁。
- 风险预警：若无可用 Linux/Windows 无线环境，Version 可能在真实环境验收项阻塞。
- 置信度：99%

#### DQ8. Linux 设备后端必须解除 STA 对热点实例与 root 权限的创建期耦合
- 问题描述：虽然 v1.1 设备业务只使用 STA，`demo/device/backends/linux/device_linux_backend.c:431` 仍无条件创建 `linux_hotspot_t`，而热点 create 在 `demo/device/backends/linux/linux_hotspot.h:17` 明确要求 root；随后 `demo/device/backends/linux/device_linux_backend.c:447` 将热点实例传给 WiFi，仅用于 `demo/device/backends/linux/linux_wifi.c:41` 读取 STA 网卡名。这会导致普通用户运行纯 STA 设备也因无 root 权限启动失败。
- 自决方案：修改 `linux_wifi_create` 为直接接收 `const char *sta_interface`，移除对 `linux_hotspot_t` 的依赖；`device_linux_backend_create` 在 v1.1 不创建 hotspot，只创建 NVS、WiFi STA 与 socket vtable。`wifi_ap_start/stop` 对该生产实例明确返回 `DEMO_ERR`，而保留 `linux_hotspot*` 源码及其独立测试，不从仓库删除。
- 自决理由：这是使已完成的 Linux STA 后端能承载 v1.1 的必要解耦，修改集中在后端装配与 WiFi 构造参数，不重写扫描/连接硬件逻辑。
- 风险预警：Linux 后端既有热点集成测试需调整为独立热点模块测试；必须新增普通用户创建 Linux STA 后端的测试，并确保旧热点能力未被误调用。
- 置信度：99%
