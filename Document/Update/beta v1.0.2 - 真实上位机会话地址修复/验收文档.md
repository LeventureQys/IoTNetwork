# beta v1.0.2 真实上位机会话地址修复验收文档

## 1. 验收组织

验收分为三部分，状态独立记录：

1. 设备端验收。
2. PC端验收。
3. 双端真实联调验收。

设备端或PC端单独通过只代表该端完成；版本最终通过必须完成第三部分。

## 2. 证据目录

```text
artifacts/beta-v1.0.2-acceptance/<YYYYMMDD-HHMMSS>/
├── device/
├── pc/
└── integration/
```

证据不得包含WiFi密码、PIN以外的敏感凭据或账号信息。

## 3. 设备端验收

### D-A1. 设备与测试工程构建

- 目的：确认设备端改动可编译。
- 前置条件：Linux、CMake、Qt6和项目依赖可用。
- 操作步骤：重新配置并构建 `demo/device` 和 `demo/tests`。
- 期望结果：命令退出0，无新增编译警告。
- 通过标准：两个工程均成功。
- 失败标准：编译、链接失败或新增警告。
- 证据要求：`device/build-device.log`、`device/build-tests.log`。

### D-A2. 真实目的地址纯逻辑

- 目的：证明根因已修复且不依赖真实WiFi测试。
- 前置条件：新增endpoint测试已编入测试目标。
- 操作步骤：运行定向gtest，输入 `192.168.1.191:5935`，真实模式为true。
- 期望结果：输出仍为 `192.168.1.191:5935`。
- 通过标准：IP和端口网络序及可读值均一致。
- 失败标准：输出loopback或端口字节反转。
- 证据要求：`device/endpoint-test.log`。

### D-A3. 模拟地址回归

- 目的：确保真实修复不破坏模拟。
- 操作步骤：运行 `SimSocket`、`HostE2E`和配网相关测试。
- 期望结果：模拟AP、Host和普通loopback测试全部通过。
- 通过标准：零失败、零崩溃。
- 失败标准：任一地址翻译或会话测试失败。
- 证据要求：`device/sim-regression.log`。

### D-A4. 连接失败资源处理

- 目的：确认上位机不可达时设备仍安全自愈。
- 操作步骤：连接未监听端口，观察返回码和状态机测试。
- 期望结果：socket关闭，返回超时/错误，设备进入HEAL且不崩溃。
- 通过标准：无句柄泄漏和异常退出。
- 失败标准：崩溃、busy loop或错误保持连接。
- 证据要求：`device/connect-failure.log`。

### D-A5. 设备日志落盘

- 目的：验证终端和文件日志单链路。
- 操作步骤：允许时短时启动设备，检查最新 `demo/logs/provision_device_dev*.log`。
- 期望结果：文件创建，包含路径、请求/实际端点；同一标记不重复；无WiFi密码。
- 通过标准：全部满足。
- 失败标准：无文件、重复、泄密或启动脚本语义变化。
- 证据要求：`device/startup.log`、日志文件副本和脱敏检查结果。
- 阻塞处理：现场不允许sudo/切换无线时标记阻塞，不得默认通过。

## 4. PC端验收

### P-A1. 启动顺序单元测试

- 目的：证明listener先于通告。
- 操作步骤：使用fake backend记录 `tcp_listen`、`mcast_join`、`mdns_register` 顺序。
- 期望结果：严格为TCP、组播、mDNS。
- 通过标准：顺序断言通过。
- 失败标准：通告组件先于listener。
- 证据要求：`pc/start-order-test.log`。

### P-A2. 启动失败回滚

- 目的：确保不通告不可用服务。
- 操作步骤：分别注入TCP失败和组播失败。
- 期望结果：TCP失败不调用组播；组播失败关闭listener；`Started()==false`。
- 通过标准：资源调用计数和状态符合。
- 失败标准：残留listener、组播或错误started状态。
- 证据要求：`pc/start-rollback-test.log`。

### P-A3. 地址有效性

- 目的：防止通告明显无效IPv4。
- 操作步骤：测试或审查unspecified、loopback、APIPA和正常LAN地址。
- 期望结果：前三类被拒绝，正常地址可选。
- 通过标准：过滤规则完整。
- 失败标准：任一无效地址可成为 `host_virtual_ip`。
- 证据要求：`pc/address-filter-test.log` 或Windows实测记录。

### P-A4. Windows构建

- 目的：确认Windows专有代码可编译。
- 环境：Windows 10/11、Visual Studio 2022、Qt6。
- 操作步骤：构建PC和tests工程。
- 期望结果：退出0，无新增警告。
- 通过标准：构建成功。
- 失败标准：编译/链接失败。
- 证据要求：`pc/windows-build.log`。
- 阻塞处理：当前Linux环境标记“待Windows环境”，不得通过。

### P-A5. Windows listener与通告

- 目的：确认真实服务端点一致且可用。
- 操作步骤：启动PC；采集日志、`Get-NetTCPConnection`/netstat和UDP 5936报文。
- 期望结果：当前PID监听 `0.0.0.0:5935`；announce为有效LAN IP和5935；日志区分两者。
- 通过标准：监听覆盖通告IP，字段一致。
- 失败标准：loopback-only、错误端口、无效IP或日志误导。
- 证据要求：`pc/listener.txt`、`pc/announce.json`、`pc/provision_pc.log`。
- 阻塞处理：无Windows环境时标记待执行。

### P-A6. 端口占用失败

- 目的：确认listener失败后不发送通告。
- 操作步骤：预占5935并启动PC，捕获日志和UDP。
- 期望结果：PC启动失败，无新的host_announce。
- 通过标准：退出非0且无通告。
- 失败标准：继续运行或发送announce。
- 证据要求：`pc/port-conflict.log`、`pc/port-conflict.pcap`。

## 5. 双端真实联调

### I-A1. 发现与实际连接一致

- 目的：证明设备连接的是PC真实地址而非loopback。
- 前置条件：设备端和PC端单独验收已通过；两端位于同一目标LAN。
- 操作步骤：启动PC，再运行设备；同步采集双方日志和抓包。
- 期望结果：PC announce端点、设备请求端点、设备实际端点完全一致；抓包显示设备IP连接PC IP:5935。
- 通过标准：不存在设备到127.0.0.1:5935的本轮尝试。
- 失败标准：任一端点不一致或真实TCP不可达。
- 证据要求：`integration/device.log`、`integration/pc.log`、`integration/session.pcap`。

### I-A2. 会话与心跳

- 目的：验证业务链路完整。
- 操作步骤：保持运行至少三个心跳周期。
- 期望结果：`device_hello -> host_ack status=ok -> ping/pong`；设备记录会话建立并确认凭据。
- 通过标准：三个周期内连接稳定，无HEAL。
- 失败标准：无ack、连接立即断开、心跳超时或进入HEAL。
- 证据要求：双方协议日志和设备事件日志解码结果。

## 6. 回归范围

- 模拟AP配网。
- 模拟Host连接和完整HostE2E。
- 设备连接失败HEAL。
- PC优雅退出host_bye。
- PC启动失败资源清理。
- 不回归Linux热点DHCP事务，除非设备启动冒烟自然覆盖。

## 7. 失败与阻塞

- 设备端失败只退回设备端工作线。
- PC端失败只退回PC端工作线。
- 联调失败先比较announce、请求、实际三个端点，再归属到对应工作线。
- Windows环境缺失只阻塞PC实机和联调项，不得把设备端已通过项改为失败。
- 任一阻塞项不得默认通过。
