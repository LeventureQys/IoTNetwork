# beta v1.0.2 实施计划导航

## 1. 执行方式

本版本按用户要求拆为两部分，分开设计、分开开发、分开提交检查：

1. 设备端：`设备端修改计划.md`。
2. PC端：`PC端修改计划.md`。

本文件不再包含混合任务，避免两端开发边界交叉。

## 2. 设备端入口

- 总计划：`设备端修改计划.md`。
- TCP任务书：`开发文档/设备端_SubStage_01_TCP地址与测试.md`。
- 日志任务书：`开发文档/设备端_SubStage_02_日志与文档.md`。
- 允许先行条件：无需等待PC端，可在当前Linux环境独立开发和测试。
- 提交门禁：设备端代码、Linux构建、单元测试和可执行启动证据单独提交用户检查。

## 3. PC端入口

- 总计划：`PC端修改计划.md`。
- 生命周期任务书：`开发文档/PC端_SubStage_01_监听生命周期.md`。
- 地址通告任务书：`开发文档/PC端_SubStage_02_地址通告与文档.md`。
- 允许先行条件：无需等待设备端，可独立修改PC代码；SubStage 02集成 `host_app.cpp` 前等待SubStage 01。
- 提交门禁：PC代码、当前环境可执行测试及Windows待验收清单单独提交用户检查。

## 4. 最终联调

只有设备端和PC端各自通过单端门禁后，才按 `验收文档.md` 第5节执行双端真实联调。任一端单独完成不代表版本最终完成。
