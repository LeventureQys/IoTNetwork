# beta v1.0.1 Linux 设备热点 DHCP 可靠性修复设计文档

## 1. 背景与目标

Windows PC 已能关联 Linux 设备热点，但现场日志显示客户端最终获得 APIPA 地址，流程在 TCP 连接前终止。当前 Linux 设备还存在真实 AP 与 STA 网段重叠、dnsmasq 系统配置未隔离、readiness 不足和失败高频重试等确定缺口。

本版本只修改 Linux 设备端与双端共用代码，使真实热点在 AP 地址、DHCP UDP 67 和 TCP 5935 都就绪后才报告成功，并通过动态选段避免本机路由冲突。禁止修改 `demo/pc/` 和 `demo/net_win/`。

## 2. 设计输入

- 需求依据：`Document/beta v1.0.0/PC日志分析与设备端DHCP修复建议_20260805.md`。
- 决策依据：同目录 `问题清单.md` 的 v2 结论。
- 当前入口：`demo/net_linux/linux_hotspot.c:160`、`demo/net_sim/sim_backend.cpp:382`、`demo/device/device_provision.c:25`、`demo/device/device_app.c:612`。
- 当前配置：`demo/config/linux_hotspot.json`。
- 当前协议常量：`demo/include/protocol.h:20`。

## 3. 范围

### 3.1 覆盖

- 严格热点配置与 IPv4/DHCP 池校验。
- 自动选择不与本机直连路由重叠的 AP 网段。
- hostapd、AP IPv4、dnsmasq PID和 UDP 67 readiness。
- dnsmasq 系统配置隔离。
- 单实例、事务回滚、资源清理和失败退避。
- NAT 默认关闭；显式启用时精确添加和删除自身规则。
- 真实 Linux 与模拟地址语义拆分。
- 自动化测试、Linux sudo 启动测试和独立无线客户端验收。

### 3.2 不覆盖

- PC 专有代码和 Windows 后端。
- TCP/JSON 消息结构。
- 应用管理 INPUT、OUTPUT 或 FORWARD 防火墙规则。
- 自动修改 `ip_forward`。
- Linux 真实模式多设备进程并行。
- 用同机 namespace/macvlan 代替真实无线客户端验收。

## 4. 总体架构

```text
有效 JSON 配置
  -> 配置解析与地址池校验
  -> rtnetlink 收集所有有效 IPv4 直连路由
  -> 首选/备用 AP 计划选择
  -> 获取真实模式单实例锁
  -> TCP 0.0.0.0:5935 listener
  -> 创建 AP 接口并启动 hostapd
  -> AP 模式检查
  -> 配置并回读 AP IPv4/prefix
  -> 隔离启动 dnsmasq
  -> PID + /proc UDP 67 readiness
  -> 可选 NAT 验证
  -> 报告“设备热点可用于配网”
```

任一步失败均关闭 TCP listener，并由热点事务逆序清理自己创建的资源；状态机进入 `provision_ap_backoff_ms` 退避。

## 6. 配置契约

`linux_hotspot_cfg_t` 增加：

```c
int prefix_length;
```

默认配置：

```json
{
  "enable": true,
  "sta_interface": "wlP2p33s0",
  "ap_interface": "ap0",
  "subnet": "10.42.0.1",
  "prefix_length": 24,
  "dhcp_start": "10.42.0.100",
  "dhcp_end": "10.42.0.200",
  "channel": 0,
  "nat": false,
  "hostapd_bin": "hostapd",
  "dnsmasq_bin": "dnsmasq",
  "work_dir": "/tmp"
}
```

真实模式配置文件必须存在、可读、非空、根为 JSON object 且不超过 1 MiB。字段缺省可使用默认值；已知字段类型错误、字符串截断或组合校验失败必须返回 `DEMO_ERR_INVAL`。

校验规则：

- `prefix_length` 为 16 至 30。
- AP、DHCP start/end 是合法 IPv4。
- AP 不是网络地址或广播地址。
- DHCP start 不大于 end，二者与 AP 同子网。
- DHCP 池不包含 AP、网络地址或广播地址。
- 接口名仅允许字母、数字、`_`、`-`、`.`，且不可为空或截断。
- `work_dir` 必须存在且可访问。

## 7. 地址与计划契约

纯逻辑内部结构统一使用主机字节序：

```c
typedef struct linux_ipv4_cidr {
    uint32_t address;
    uint32_t network;
    uint32_t netmask;
    uint32_t broadcast;
    uint8_t prefix_length;
} linux_ipv4_cidr_t;

typedef struct linux_ipv4_route {
    linux_ipv4_cidr_t destination;
    unsigned int ifindex;
    char interface_name[32];
    unsigned int table;
} linux_ipv4_route_t;

typedef struct linux_hotspot_plan {
    linux_ipv4_cidr_t ap;
    uint32_t dhcp_start;
    uint32_t dhcp_end;
    int candidate_index;
    int used_fallback;
} linux_hotspot_plan_t;
```

候选顺序：

1. 配置首选 `subnet/prefix_length`，默认 `10.42.0.1/24`。
2. `10.43.0.1/24`。
3. `172.31.250.1/24`。
4. `192.168.250.1/24`。

DHCP 池通过首选网络中的 host offset 重定位到备用网络。候选无法容纳 offset 时跳过。候选与任一直连路由满足以下条件即冲突：

```text
candidate.network <= route.broadcast &&
route.network <= candidate.broadcast
```

全部候选冲突、路由查询失败或结果截断时拒绝启动。

## 8. Linux 系统操作契约

### 8.1 路由

- 使用 rtnetlink `RTM_GETROUTE`。
- 接受 `AF_INET`、`RTN_UNICAST`、存在 `RTA_OIF`、无 `RTA_GATEWAY` 且接口 UP 的路由。
- 检查所有路由表，忽略 local、broadcast、blackhole 和 unreachable 类型。
- 不解析 `ip route` 文本。

### 8.2 单实例

- 锁文件：`<work_dir>/modu_linux_hotspot.lock`。
- `open(O_CREAT|O_RDWR, 0600)` 后 `flock(LOCK_EX|LOCK_NB)`。
- 锁由 init 持有至 deinit；文件不删除，锁内写 PID。
- 锁冲突时 backend 创建失败，设备入口退出，不进入状态机重试。

### 8.3 子进程

- 使用 `fork/execvp` argv，不把配置值拼入 `/bin/sh -c`。
- 子进程关闭 3 以上继承 fd；父进程等待并返回准确退出码。
- 不使用 `killall`、`pkill` 或杀死系统 dnsmasq。

## 9. 热点启动事务

顺序固定为：

1. 检查 init、enable、root 和依赖程序。
2. 采集直连路由并选择最终计划。
3. 确认 AP 接口未被未知资源占用。
4. 创建 AP 接口并设置 NetworkManager unmanaged。
5. 写配置并启动 hostapd。
6. 验证接口类型为 AP。
7. 配置最终 AP IPv4/prefix。
8. 使用 `getifaddrs()` 回读精确地址和掩码。
9. 启动 dnsmasq。
10. 最多等待 2 秒验证 PID和 UDP 67。
11. 记录防火墙部署要求。
12. 可选配置 NAT。
13. 设置 active 并返回成功。

`g_active=1` 和“热点已启动”日志只能出现在第 10 至 12 步全部通过之后。

## 10. dnsmasq 契约

argv 必须包含：

```text
--conf-file=/dev/null
--port=0
--bind-interfaces
--interface=<ap_interface>
--listen-address=<final_ap_ip>
--dhcp-authoritative
--dhcp-range=<start>,<end>,<netmask>,12h
--dhcp-option=option:router,<final_ap_ip>
--dhcp-option=54,<final_ap_ip>
--pid-file=<work_dir>/dnsmasq_modu_ap.pid
--log-dhcp
```

readiness 必须确认 pidfile 是有效 PID、进程存活、其 fd 中的 socket inode 出现在 `/proc/net/udp`，端口为 67，绑定地址是最终 AP 地址或 `0.0.0.0`。UDP 67 被其他进程占用时不得杀占用者。

## 11. NAT 与防火墙

- 默认 `nat=false`。
- 应用不添加 INPUT、OUTPUT 或 FORWARD ACCEPT 规则。
- 当前部署环境已由 UFW 持久放行 `ap0` UDP 67 和 TCP 5935；阶段四仍需端到端验证。
- NAT 显式启用时要求 `/proc/sys/net/ipv4/ip_forward == 1`，添加一条带 comment 的精确 MASQUERADE：源为最终 AP CIDR，出口为 STA。stop 时删除完全相同规则。
- NAT 失败视为显式配置无法满足，热点事务回滚；程序不修改 ip_forward。

## 12. 回滚与所有权

失败按逆序清理：NAT、dnsmasq、pidfile、AP 地址、hostapd、pidfile/配置、AP 接口。只清理由当前事务创建且能证明所有权的资源。

- AP 接口已存在但所有权未知：失败，不删除。
- pidfile 指向非预期进程：不 kill，记录资源冲突。
- cleanup 错误追加日志，但不得覆盖首个启动根因。
- stop 幂等；停止后不残留 `ap0`、产品子进程、pidfile、hostapd 配置或 NAT 规则。

## 13. 状态机契约

`prov_server_start()` 失败时：

```c
evlog_record(app, "配网热点启动失败，等待退避后重试");
app->boot_backoff_until =
    now + (uint64_t)app->params->provision_ap_backoff_ms;
device_set_state(app, DEV_STATE_BOOT);
return;
```

失败分支不再固定 sleep 100 ms。退避期间不得调用 AP start；日志打印退避时长。

## 14. 共用地址语义

- `PROTO_AP_IP` 改为 `PROTO_SIM_AP_IP`，数值仍为 `192.168.1.1`。
- 该常量只用于模拟地址翻译和模拟测试。
- 真实 Linux 配网 TCP 端点为“设备 DHCP router 地址:5935”。
- 真实 Linux 代码不得引用模拟常量。
- 不修改 TCP/JSON 协议，也不修改 PC 专有代码。

## 15. 测试策略

- 纯逻辑：配置、prefix、地址池、候选顺序、宽/窄路由重叠、池重定位。
- 注入式运行时：每个启动阶段失败、readiness 超时、错误 PID/inode、逆序回滚、NAT 和幂等 stop。
- 状态机：失败进入 BOOT、退避期不重试、到期只重试一次。
- 回归：模拟地址数值、虚拟端口映射和完整模拟配网保持不变。
- Linux 启动：sudo 真实启动、候选切换、非法配置、UDP 67、TCP 5935、20 次启停。
- 端到端：独立无线客户端必须获得合法 DHCP 租约、router 并连接 5935；Windows PC 运行现有程序完成 auth。无法执行时标记阻塞。
