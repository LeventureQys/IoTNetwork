## 3. 数据契约

### 3.1 配置字段

```c
int provision_handoff_grace_ms;
```

- 位置：`demo_params_t` 阶段二字段。
- 默认值：1000。
- JSON 字段名必须完全一致。
- 负值加载后按 0 使用，或在参数加载后归零；不得转换为超大无符号等待值。

### 3.2 运行字段

```c
uint64_t provision_handoff_deadline_ms;
```

- 位置：`device_app_t` 阶段二字段。
- `0` 表示没有待执行的自动交接。

## 4. 实现步骤

### 4.1 初始化

在 `prov_server_start()` 中重置：

```c
app->provision_handoff_deadline_ms = 0;
```

确保每次新 AP 会话不会继承上一次交接计时。

### 4.2 wifi_config 成功路径

现有顺序保持：

1. 连接目标 WiFi。
2. 校验 IP 和 SSID。
3. 保存未确认凭据。
4. 设置 `provision_wifi_ok=1`。
5. 发送 `wifi_result ok`。

只有 `prov_reply()` 对应的发送成功后，才设置：

```c
app->provision_handoff_deadline_ms =
    net_time_ms(app->net) + max(0, app->params->provision_handoff_grace_ms);
```

如果当前 `prov_reply()` 无返回值，应把它改为返回 `device_send()` 的结果，并只调整本文件调用方；不得引入 Linux 专属处理。

发送失败时：

- 记录警告。
- 允许配网连接关闭事件或后续状态机按已成功配置的事实完成交接。
- 不回滚已经验证成功并保存的目标 WiFi。

为避免“发送失败后永远不交接”，无论发送成功或失败，最终都必须安排 deadline；日志要区分发送结果。实现时可先发送再统一设置 deadline。

### 4.3 close_ap 路径

收到 `CMD_CLOSE_AP` 时：

- 如果 `provision_wifi_ok==1`：清零 deadline，调用 `prov_server_stop()`。
- 如果 `provision_wifi_ok==0`：保持现有“过早 close_ap 视为失败”的状态机保护，不允许进入 discovery。
- 重复调用 `prov_server_stop()` 必须安全。

### 4.4 自动交接路径

在 `sm_ap_provision()` 调用 `prov_server_poll()` 后、AP 空闲超时判断前增加：

```text
如果 provision_wifi_ok == 1
且 deadline 已设置
且 now >= deadline
则记录自动交接日志
调用 prov_server_stop()
清零 deadline
继续使用现有 ap_listen == NULL 分支进入 discovery
```

进入 discovery 前继续调用现有 `ensure_expected_wifi_or_recover(app, "关闭热点前", 1)`，不复制 WiFi 校验逻辑。

### 4.5 超时修正

`prov_server_poll()` 中“等待 wifi_config 超时”条件增加：

```text
provision_wifi_ok == 0
```

成功交接阶段不得关闭连接并打印 wifi_config 超时。

### 4.6 停止和失败清理

以下路径清零 deadline：

- `prov_server_start()`。
- `prov_server_stop()`。
- 配网失败后重新等待配置时。
- 进入重新配网或销毁流程时。

不要在仅关闭客户端 socket、但仍需自动交接的路径过早清零 deadline。

### 4.7 discovery 日志

`net_udp_mcast_join()` 返回 `DEMO_OK` 后记录：

```text
服务发现：UDP 组播监听已启动，地址=%s:%d
```

参数来自 `app->params->mcast_group` 和 `mcast_port`，不得硬编码日志值。

## 5. 测试要求

### 5.1 参数测试

- 默认 `provision_handoff_grace_ms == 1000`。
- JSON 可覆盖该值。
- 0 值可加载。

### 5.2 配网正常测试

保留既有 `FullFlowAuthConfigClose`：

- auth 成功。
- wifi_config 成功。
- 发送 close_ap。
- 设备进入 discovery。

### 5.3 新增自动交接测试

新增测试建议命名：

```text
Provision.WifiSuccessWithoutCloseApAutoEntersDiscovery
```

步骤：

1. 将 grace 设置为较短测试值，如 100ms。
2. 完成 auth 和 wifi_config。
3. 验证 wifi_result ok。
4. 不发送 close_ap。
5. 等待设备进入 `DEV_STATE_DISCOVERY`。
6. 验证测试未依赖 AP idle timeout。

### 5.4 失败保护测试

新增或复用测试验证：

- wifi_config 参数失败时，等待超过 grace 也不能进入 discovery。
- 未收到 wifi_config 时连接关闭不能进入 discovery。

## 6. 禁止事项

- 不新增 `device_state_t`。
- 不实现 WiFi 重连退避修复。
- 不修改真实 mDNS。
- 不把 Linux API 写进 `demo/device/`。
- 不删除 `close_ap` 协议。
- 不改变 wifi_result JSON 字段。
- 不修改凭据确认窗口语义。
