# 验收文档 - beta v1.0.4（硬件抽象层文档化 + 联调消息发送功能）

## 1. 验收范围

**覆盖**：

- 上位机界面"发送消息"功能（选中在线设备 → 发送 `app_data` 调试文本 → 设备侧日志展示）；
- 设备端界面"发送消息"功能（会话态 → 发送 `app_data` 调试文本 → 上位机侧日志展示）；
- 两端对 `app_data` 接收的展示升级（从"已忽略"到展示文本）；
- 边界防护：空消息/超长（>512 字节）/非会话态/离线设备的拒绝行为；
- 《硬件抽象层接口规范》与《硬件抽象层移植指南》两份文档的内容完整性与准确性；
- `demo/README.md`、`demo/net_esp32c2/README.md` 的层次说明与文档索引更新；
- 全量既有测试回归。

**不覆盖**：

- ESP32-C3 真机验证（无硬件环境；移植指南为文档交付，其正确性以"与接口规范/骨架代码一致"为验收标准，不以真机跑通为标准）；
- 协议常量变更（本版本明确不改，验收反而要确认常量未被动过，见 C7）；
- Windows 真实 WiFi 配网路径（既有功能，不在本版变更面内，仅冒烟）。

## 2. 验收环境

| 项 | 要求 |
|----|------|
| 构建机 | Windows 10/11 + MSVC 2022 + CMake ≥ 3.20 + Qt 6 Widgets；或 Linux（rk3588 OrangePi 验证机，gcc + CMake + Qt6） |
| 运行模式 | sim 模拟模式（`provision_pc --sim` / 设备端默认 sim 后端）；两端同一宿主机即可 |
| 测试数据 | `demo/config/demo_config.json` 默认配置；`run/` 目录 NVS（测试用 `--fresh` 或清理 `run/dev*.nvs.json`） |
| 外部服务 | 无（sim 模式不依赖真实 WiFi/路由器） |

## 3. 前置条件

1. 仓库处于 beta v1.0.4 开发完成状态（阶段三完成报告已提交）。
2. 构建目录干净：删除或忽略既有 `demo/pc/build`、`demo/device/build`、`demo/tests/build-msvc` 的旧产物（可复用但需重新全量编译）。
3. 无残留进程占用 5935/5936 端口与 23000+ 设备 AP 端口段。

## 4. 验收项列表

### 第一层：编译测试

#### C1. 全量编译通过
- 目的：确认两端与测试工程零编译错误、无新增警告。
- 前置条件：环境满足 §2。
- 操作步骤：
  1. `cmake -S demo/pc -B demo/pc/build`（带 Qt 前缀）→ `cmake --build demo/pc/build --config Debug`；
  2. `cmake -S demo/device -B demo/device/build` → 同法构建；
  3. `cmake -S demo/tests -B demo/tests/build-msvc` → 同法构建。
- 期望结果：三个工程全部编译链接成功。
- 通过标准：0 error；与上一版本相比无新增 warning。
- 失败标准：任一 error 或新增 warning。
- 证据要求：三份编译日志存档（如 `run/v104_build_pc.log` 等）。

### 第二层：启动测试

#### S1. 上位机启动与新入口可见
- 目的：确认上位机无崩溃启动且"发送消息"入口存在。
- 操作步骤：启动 `provision_pc --sim`；观察主窗口。
- 期望结果：窗口正常显示（设备表、日志窗、流程进度）；按钮行存在"发送消息"按钮与消息输入框；日志无 ERROR。
- 通过标准：启动 30 秒无崩溃；入口可见。
- 失败标准：崩溃、入口缺失、启动日志含 ERROR。
- 证据要求：窗口截图（标注发送入口）+ 启动日志片段。

#### S2. 设备端启动与新入口可见
- 目的：确认设备端无崩溃启动且"发送消息"入口存在。
- 操作步骤：启动 `provision_device --device-index 0 --fresh`。
- 期望结果：窗口正常显示（状态区、日志窗、故障注入行）；控制行存在"发送消息"按钮与消息输入框。
- 通过标准/失败标准/证据要求：同 S1。

### 第三层：功能完整性测试

#### F1. 上位机 → 设备 发送联调消息
- 目的：验证 host 侧发送链路端到端。
- 前置条件：S1/S2 通过；两端完成配网且设备进入"会话在线"（设备表状态列显示"在线"）。
- 操作步骤：上位机设备表选中该设备行 → 输入框输入"联调测试-上位机" → 点"发送消息"。
- 期望结果：上位机日志出现"联调消息已提交发送"与"已向 <id> 发送调试消息"；**设备端**日志出现"会话：收到上位机调试消息：联调测试-上位机"。
- 通过标准：两端日志均出现且文本一致。
- 失败标准：任一端缺失日志或文本不符。
- 证据要求：两端日志片段 + 操作记录。

#### F2. 设备 → 上位机 发送联调消息
- 目的：验证 device 侧发送链路端到端。
- 前置条件：会话在线。
- 操作步骤：设备端输入"联调测试-设备" → 点"发送消息"。
- 期望结果：设备端日志"会话：已向上位机发送调试消息"；**上位机**日志"收到来自 <id> 的调试消息：联调测试-设备"。
- 通过/失败标准、证据要求：同 F1。

#### F3. 边界拒绝行为
- 目的：验证空/超长/非会话态/离线的拒绝。
- 操作步骤与期望：
  1. 设备未进入会话态时点设备端"发送消息" → 日志"发送失败：未在会话状态或消息为空/超长"，无崩溃；
  2. 上位机未选中设备行点"发送消息" → 日志"请先在设备表中选择要发送消息的设备"；
  3. 输入超过 512 字节文本发送 → 对应端日志提示超长，无帧发出（对端无"收到…调试消息"日志）；
  4. 上位机选中离线设备发送 → 日志提示离线，或入队后冲刷日志"调试消息丢弃"。
- 通过标准：四种情形均按期望拒绝且进程无崩溃。
- 证据要求：四种情形的日志片段。

#### F4. 单元测试（新增用例）
- 目的：验证 app_data 发送路径的可测试覆盖实际执行通过。
- 操作步骤：运行 `demo/tests` 全量测试，筛选 `HostAppData.*`、`DeviceAppData.*` 用例。
- 期望结果：`HostAppData.SendToDevice`、`HostAppData.RejectInvalid`、`DeviceAppData.SendToHost`、`DeviceAppData.RejectWhenNotSession`、`DeviceAppData.RejectEmptyAndTooLong` 全部 PASS。
- 通过标准：5/5 PASS。
- 证据要求：ctest 输出（`demo/tests/run/unit_tests.log` 或等价存档）。

#### D1. 《硬件抽象层接口规范》完整性
- 目的：验证文档交付物满足任务书章节契约。

- 通过标准：章节齐全；29/29 接口覆盖；抽查无虚构。
- 失败标准：章节缺失、接口遗漏、虚构调用点。
- 证据要求：章节清单核对表 + 抽查记录。

#### D2. 《硬件抽象层移植指南》完整性与一致性

#### D3. README 更新

## 5. 失败与阻塞处理

- C1 失败 → 退回阶段三定位编译错误。
- S1/S2 失败 → 退回阶段三；若为环境问题（Qt 缺失、端口占用）记录阻塞原因并重试。
- F1~F4 单项失败 → 定位到对应 SubStage（01 或 02）修复后重验该项与其回归项。
- D1~D3 失败 → 退回对应 SubStage（03 或 04）补文档；验收标准理解歧义时先修订任务书再重验。
- C5/C6 失败 → 定位异常用例/日志差异，修复后全量重跑。
- 无法执行的验收项（如需真机）→ 记为"阻塞"并注明原因，不得默认通过（本版本已将真机项移出范围，正常不应出现）。
