### 1.2 芯片与文档沿革

原文档基于 ESP32-C3 编写；本版本按实际目标芯片 **ESP32-C2**（ESP8684，RISC-V 单核 120MHz）重设计。二者在 ESP-IDF 下的 WiFi（SoftAP/Station）与 lwIP 网络 API 兼容，本流程设计同时覆盖两芯片。

### 1.3 环境假设（工厂局域网离线场景）

- 本流程面向**工厂局域网**环境：目标 WiFi 为工厂内部网络，路由器与设备**可能无法连接互联网**。
- 全部核心功能均在局域网内完成，**不依赖互联网**：配网（SoftAP 直连）、服务发现（mDNS/组播）、TCP 连接、心跳保活、时间同步（以上位机为局域网时间源）。
- 互联网依赖仅存在于可选增强：外网 NTP 校时（默认禁用）、OTA 远程升级（远期，见附录 B）。工厂场景下 NTP 留空禁用，OTA 走局域网升级通道。
- 上位机本地时钟应保持准确（可联网时自动校时，离线时由管理员手动设置），作为局域网时间源为设备提供时间。

## 2. 系统总览

### 2.1 角色与拓扑

| 角色 | 说明 |
|------|------|
| **嵌入式设备** | ESP32-C2 传感器设备。支持 SoftAP 配网、STA 接入 WiFi、mDNS/组播服务发现、作为 TCP 客户端连接上位机 |
| **上位机** | PC 端控制软件。承担配网工具、TCP 服务器、组播/mDNS 通告、设备注册表与质量统计管理 |

拓扑：所有设备与上位机处于同一局域网（配网阶段除外，此时上位机临时连接设备热点）。

### 2.2 五阶段流程总览

```text
阶段一：启动与自检        NVS 读取（含配置版本校验）→ 上电错峰 → WiFi 连接（reason code 错误分类 + 退避重试）→ 配网判定 → 时间同步（局域网源）
阶段二：配网（SoftAP）     WPA2 热点 + 一次性 PIN 会话认证 → wifi_config（输入校验）→ wifi_result → close_ap
阶段三：服务发现            mDNS 主 → UDP 组播兜底 → 已存主机候选列表直连（三级降级）
阶段四：连接与会话保活      TCP + device_hello/host_ack（session_id 续接 + proto_ver 版本协商）+ 心跳 ping/pong（带序号）+ 长度前缀帧
阶段五：异常自愈            错误分类（reason code）→ 指数退避+抖动重连 → RSSI 监测 → 降级链 → 看门狗
管理维度：多设备注册表 + 参数集中配置 + 安全（WPA2/PIN/group key）+ 可观测性（事件日志/诊断上报）+ 传输健壮性（帧/限速）
```

正文组织：**第 3 章**按阶段展开主流程；**第 4 章**定义协议报文与参数；**第 5 章**为贯穿所有阶段的横切保障机制；**第 6 章**为附录。

## 3. 主流程（五阶段详解）

### 3.1 第一阶段：启动与自检

![Fig002A 设备启动自检流程](figures/Fig002A_设备启动自检流程.png)

*图 Fig002A：设备启动自检（阶段一）。NVS 读取与配置版本校验 → 上电错峰 → WiFi 连接（reason code 分类）→ 多凭据切换 → 配网判定。*

1. ESP32-C2 上电，读取 NVS 中保存的配置：WiFi 凭据（SSID+密码，最多 2 组：主/备，切换策略见第 5 条）、上次成功连接的主机候选列表（IP+port，最多 2 条）、事件日志、运行计数。
2. **配置版本校验**：NVS 配置携带 schema 版本号（当前为 1）。版本不匹配（固件升级后）→ 按迁移规则升级（保留可迁移字段）；无法迁移 → 清除配置并进入第二阶段（配网模式）。见 5.4 节"配置管理"。
3. **上电错峰（新增）**：上电后先执行随机延迟 0~10s（工厂多设备同时上电时避免同步连接风暴，Azure 重连指南的同类风险），延迟期间完成自检、LED/日志初始化。
4. **无 WiFi 配置** → 直接进入第二阶段（配网模式）。
5. **有 WiFi 配置** → 尝试连接（STA 模式），按 **WiFi reason code**（ESP-IDF `WIFI_REASON_*`）分类分流：

   | reason code | 含义 | 分类 | 处理 |
   |-------------|------|------|------|
   | 202（AUTH_FAIL）/ 203 / 204 | 认证失败/密码错误 | 不可恢复 | 记录错误原因，直接进入配网模式（不再重试） |
   | 201（NO_AP_FOUND） | 信号太弱/AP 不可见 | 可恢复 | 指数退避重试 |
   | 205（HANDSHAKE_TIMEOUT）等 | 握手超时/路由器异常 | 可恢复 | 指数退避重试 |

   - 可恢复错误退避序列：1s、2s、4s、8s、16s、30s（上限），每次叠加 0~5s 随机抖动；**连续 5 次失败**后才进入配网模式。
   - **多凭据集 fallback（v3）**：当前（主）凭据集连续 5 次失败且存在备用凭据集 → 自动切换备用集并从 1s 退避重新尝试；全部凭据集耗尽才进入配网模式。此为成熟 IoT 设备常见的多网络 fallback 能力，应对主网络临时故障/停用/更换路由器的场景，减少现场重新配网。
6. 连接成功 → 进入第三阶段（服务发现）。
7. 状态指示（真实设备为 LED，模拟环境为日志）：
   - 未配网 / 配网模式：红色慢闪
   - STA 连接中：黄色快闪
   - 已连接上位机：绿色常亮
   - 错误：红色快闪（配网失败时）
8. **时间同步（v2 起必选，局域网时间源优先，适配工厂离线场景）**：设备连接上位机成功后，在注册握手（host_ack 的 `server_time` 字段，见 3.4 节第 29 条）中获取上位机时间并校准本地时钟（秒级精度，用于日志时间戳与诊断，不阻塞业务）；每次重连自动重新校准。**可选增强**：若参数表配置了 NTP 服务器且工厂网络可访问外网（默认留空 = 禁用），后台尝试 NTP 同步，失败每 15 分钟重试。时间同步完成前，事件日志使用 boot 相对时间戳，同步后换算为绝对时间。

### 3.2 第二阶段：配网（SoftAP 会话模式）

> 前提：上位机界面上已提前填写好目标 WiFi 的 SSID 和密码。
> 限制说明：SoftAP 方案要求上位机临时连接设备热点，配网期间上位机自身网络中断，且一次只能配一台设备（串行）。BLE 配网（Blufi）可作为多设备并行配网的可选增强，见附录 A。
> v2 安全增强：**热点本身开启 WPA2 加密，配网会话在加密信道内再进行 PIN 认证，形成双因子防护**（借鉴乐鑫 Unified Provisioning 的"WPA2 传输安全 + PoP"组合）。

#### 3.2.1 设备侧

![Fig002B 设备配网流程](figures/Fig002B_设备配网流程.png)

*图 Fig002B：设备配网（阶段二）。WPA2 热点 + 一次性 PIN 会话认证 → wifi_config 输入校验 → 配网确认（连接成功才写 NVS）→ wifi_result → close_ap。*

9. 开启 WiFi 热点（AP 模式），SSID 固定为 `Modu_XXXX`：
   - `XXXX` = 设备 MAC 地址的后 4 位（大写十六进制），用于区分多台设备。
   - 例如：MAC `AA:BB:CC:DD:EE:FF` → 热点名 `Modu_EEFF`。
   - **热点启用 WPA2-PSK 加密**：密码为设备出厂唯一密码（每台设备不同，打印在设备标签/说明书，模拟环境输出到控制台）。该密码同时充当乐鑫 PoP（proof-of-possession）：只有物理持有设备的人才能连接热点，防止他人蹭热点干扰配网。
10. 在 AP 网关地址 `192.168.1.1:5935` 启动 TCP 服务器，并**生成一次性配网 PIN**（4 位数字，通过设备标签、LED 编码或日志展示；模拟环境中直接输出到控制台）。**PIN 认证成功后立即作废**（防重放：下一次配网需重新生成，旧 PIN 失效）。
11. **会话认证**：客户端连接后必须在 10 秒内发送：

    ```json
    {"cmd":"auth","pin":"1234"}
    ```

    - PIN 正确 → 进入"可配网"会话状态（该 PIN 随即作废），等待 wifi_config。
    - PIN 错误 → 回复 `{"cmd":"auth_result","status":"fail"}` 并断开；**连续 5 次认证失败** → 关闭热点，退避 5 分钟后重试本阶段。
    - 超时未认证 → 断开连接。
12. 认证通过后等待配网信息（**60 秒超时**，超时后断开连接，保持热点继续等待）。**收到后先做输入校验**：

    ```json
    {"cmd":"wifi_config","ssid":"目标WiFi名称","password":"目标WiFi密码"}
    ```

    - SSID 非空且长度 ≤ 32 字节。
    - 密码长度 8~63（WPA2 约束；开放网络允许空密码时跳过）。
    - **目标 WiFi 必须为 2.4GHz**（ESP32-C2 仅支持 2.4G，5G SSID 设备无法连接；频段校验由上位机侧完成，见第 19 条）。
    - 校验失败 → 回复 fail + reason，保持 AP 等待重试，不写入 NVS。
13. 校验通过后（**配网确认，v3**）：
    - 先尝试连接目标 WiFi（STA 模式），按 3.1 节第 5 条的 reason code 错误分类处理（密码错误立即判定失败，信号弱重试 3 次）。
    - **连接成功后才**将 SSID、密码与配置版本号写入 Flash（NVS 分区，掉电不丢失），新配置标记为"未确认"（连接失败则不动 NVS，旧配置仍有效）。
    - **确认窗口**：新配置生效后 120 秒内成功连接上位机（阶段三/四完成）→ 标记"已确认"并成为回滚基准（last-known-good）；未确认即重启的，下次启动自动回滚到上一凭据集，防止"换了网络却找不到上位机"的状态被固化。
    - 通过同一条 TCP 连接回复结果：

    ```json
    // 连接成功
    {"cmd":"wifi_result","status":"ok","device_ip":"192.168.1.100"}

    // 连接失败（保持 AP 模式，等待上位机修正后重发）
    {"cmd":"wifi_result","status":"fail","reason":"密码错误 / 信号太弱 / 目标为5G网络 / 超时"}
    ```

14. **失败处理**：回复 fail 后设备**保持 AP 模式与 TCP 服务器**，继续接受新的 auth + wifi_config 重试，直到热点超时。
15. 收到 `{"cmd":"close_ap"}` 后：
    - 关闭热点（AP 模式）。
    - 保持 STA 模式下的 WiFi 连接。
    - 进入第三阶段。
16. **热点超时保护**：AP 开启后 **120 秒**内无任何客户端完成认证 → 关闭热点，**退避 5 分钟后**回到第一阶段重新判断。

#### 3.2.2 上位机侧

![Fig001A 上位机配网流程](figures/Fig001A_上位机配网流程.png)

*图 Fig001A：上位机配网流程。扫描设备热点（标注频段）→ 连接 Modu_XXXX 热点 → WPA2 密码 + PIN 双因子认证 → wifi_config → wifi_result → close_ap → 切回目标 WiFi。*

17. 扫描周边 WiFi 热点，过滤出所有以 `Modu_` 开头的热点。
18. **频段提示**：扫描时标注各 WiFi 的频段，提示用户目标 WiFi 必须为 **2.4GHz**（若目标网络只有 5G，需在路由器开启/选用 2.4G SSID，否则设备无法连接）。
19. 用户选择目标设备（如 `Modu_EEFF`），上位机提示"将临时断开当前网络"，连接该热点（**需要输入热点 WPA2 密码 + 配网 PIN，均从设备标签/日志获取**）。
20. 通过 TCP 连接 `192.168.1.1:5935`，发送 auth（PIN 由用户从设备标签/日志获取输入，或 Demo 中自动读取），认证通过后发送 wifi_config。
21. 等待 wifi_result：
    - **成功** → 发送 `{"cmd":"close_ap"}` 通知设备关闭热点；上位机断开 `Modu_XXXX` 热点，重新连接回目标 WiFi（Windows 下自动切回失败时提示用户手动操作）。
    - **失败** → 按 reason 提示用户（密码错误/信号弱/5G 网络/超时），修正后重新发送配网信息，或放弃该设备。
22. **多设备配网**：上位机以串行队列方式依次连接多个 `Modu_XXXX` 热点逐个配网（SoftAP 固有限制）。建议配网顺序记录到本地队列，失败设备可重试。

### 3.3 第三阶段：服务发现（三级降级）

> 问题：配网完成后，设备不知道上位机在目标 WiFi 下的 IP 地址。
> 方案：采用 主（mDNS）→ 兜底（UDP 组播）→ 保底（已存主机候选列表） 三级发现，任一通道成功即可进入第四阶段。

![Fig002C 设备服务发现流程](figures/Fig002C_设备服务发现流程.png)

*图 Fig002C：设备服务发现（阶段三）。mDNS → UDP 组播 → 候选列表直连 三级降级。*

23. **一级：mDNS/DNS-SD（首选）**
    - 上位机启动时注册 mDNS 服务 `host._tactile._tcp.local`（携带 IP 与 tcp_port 的 TXT 记录）。
    - 设备解析 `host._tactile._tcp.local` 获取上位机 IP 与端口；解析失败时退化到二级。
24. **二级：UDP 组播（兜底）**
    - 上位机持续向 `224.0.2.1:5936` 发送通告包（间隔 1 秒）：

    ```json
    {"cmd":"host_announce","proto":1,"seq":12345,"ip":"192.168.1.50","tcp_port":5935}
    ```

    - `proto`：协议版本（当前 1），设备校验，版本不符忽略。
    - `seq`：单调递增序列号，设备据此忽略乱序/重复包。
    - `ip`：上位机在目标 WiFi 下获取到的 IP；`tcp_port`：TCP 服务器监听端口（默认 5935）。
    - **可选防伪**：若启用接入认证（group key 开启），host_announce 附带 `mac`（由 group key 派生的一次性 HMAC，默认关闭）。局域网内中危威胁，默认不启用。
    - 设备加入组播组监听；**配网完成后前 30 秒**采用 500ms 快速轮询以加速首次发现。
    - 组播地址 `224.0.2.1` 的选取依据见附录 C。
25. **三级：主机候选列表（v2 升级，保底）**
    - 设备将最近成功连接的上位机（IP+port，最多 2 条：主/备，带 last_seen）写入 NVS。
    - 若 30 秒内 mDNS/组播均未发现上位机（组播可能被路由器屏蔽，或上位机更换了 IP），设备依次尝试候选列表中的地址（主优先，失败换备）。
    - 上位机 IP 因 DHCP 租约变化时，主地址失效 → 自动切换备地址，或回到组播/mDNS 通道刷新。
26. 全部三级通道均失败 → 按阶段五的退避策略循环重试（上限 30s，避免风暴）。
27. **host_bye 优雅下线（新增）**：上位机正常退出前，向组播地址广播 `{"cmd":"host_bye","seq":N}`；设备收到后**立即**停止等待通告，转用主机候选列表直连（或进入 30s 快速轮询），无需等待心跳超时（默认 15s）即可发起重连——显著缩短"上位机关机 → 设备感知"的延迟。

### 3.4 第四阶段：连接与会话保活

![Fig002D 设备连接与自愈流程](figures/Fig002D_设备连接与自愈流程.png)

*图 Fig002D：设备连接与自愈（阶段四/五）。注册握手（长度前缀帧 + proto_ver）→ 心跳保活 → RSSI 监测 / 异常降级链。*

28. 设备以 **TCP 客户端**身份连接上位机（地址来自阶段三任一级发现）。
29. **注册握手**：连接建立后，设备必须立即上报自身信息：

    ```json
    {"cmd":"device_hello","id":"AA:BB:CC:DD:EE:FF","type":"pressure_sensor","fw_version":"1.0.0","proto_ver":1,"capabilities":["pressure"],"uptime":3600}
    ```

    - `id`：设备 MAC 地址（全量）；`uptime`：设备运行秒数（自上次上电）。
    - `proto_ver`（v3 新增）：设备支持的消息协议版本（当前 1），上位机据此做版本协商（见 host_ack）。
    - **重连续接语义（v2 新增）**：若是断线重连（设备仍保留上次会话），hello 携带 `session_id` 字段（上次 host_ack 下发的值）；上位机据此区分"全新注册"与"续接重连"，用于旧连接清理与状态恢复。无该字段视为全新会话。
    - 上位机校验设备 ID 是否在允许列表（若启用接入认证，见 5.3 节"安全说明"）；校验通过后回复：

    ```json
    {"cmd":"host_ack","status":"ok","heartbeat_interval":10,"session_id":"...","server_time":1785936000,"proto_ver":1,"fw_min_req":"1.0.0"}
    ```

    - `heartbeat_interval`：心跳间隔（秒），设备按此值发送心跳。
    - `server_time`：上位机当前 Unix 时间戳（秒），设备据此校准本地时钟——工厂离线环境下的局域网时间源（见 3.1 节第 8 条）。
    - `proto_ver`（v3 新增）：本连接实际生效的协议版本（取双方支持版本的交集）；设备版本低于上位机最低支持版本时，上位机回复 `status="fail"` + reason 并断开，日志记录待升级设备清单。
    - `fw_min_req`（v3 新增）：上位机要求的最低固件版本；设备固件低于该值仅记录告警并可通过 diag_report 呈现（提示不阻断），与 OTA 升级方向（附录 B）衔接。
    - **连接数已满（新增）**：上位机连接数达上限（默认 16）时，回复 `{"cmd":"host_ack","status":"busy"}` 并断开；设备收到 busy 后按 60s 长退避重试（见 3.5 节第 33 条），避免反复敲门。
    - 校验失败 → 上位机断开连接。
30. **心跳保活（MQTT Keep Alive 语义 + 序号）**：
    - 设备每 `heartbeat_interval`（默认 10 秒）发送 `{"cmd":"ping","seq":N}`（seq 单调递增，防重放/乱序，上位机可统计丢包率）；上位机回复 `{"cmd":"pong"}`。
    - 上位机在 `1.5 × heartbeat_interval`（15 秒）内未收到设备的任何报文 → 判定设备断线，清理该连接。
    - 设备在 `1.5 × heartbeat_interval` 内未收到上位机任何报文（含 pong 与其他下行数据）→ 判定连接失效，进入第五阶段重连。
    - 底层同时启用 TCP Keep-Alive 作为辅助检测。
31. 连接建立期间，双方可收发业务数据（传感器数据流等，超出本文档范围）。

### 3.5 第五阶段：异常自愈

#### 3.5.1 错误分类（v2 细化，按 WiFi reason code）

| 错误类型 | 判定依据 | 处理 |
|----------|----------|------|
| 不可恢复 | 配网 PIN 连续错误、WiFi 认证失败（AUTH_FAIL 202）、设备接入认证失败 | 停止重试，进入配网模式或等待人工干预 |
| 可恢复（网络层） | TCP 断线、心跳超时、mDNS/组播无响应、NO_AP_FOUND（201）/握手超时（205） | 按指数退避 + 抖动重试，直到成功或达到降级条件 |
| 可恢复（信号质量） | 连接成功但 RSSI 持续低于阈值（-75dBm） | 事件日志记录 + 主动重连（见第 32 条） |

#### 3.5.2 设备侧降级链

32. **RSSI 信号监测（新增）**：连接期间周期采样信号强度（默认 5s 一次）。**连续 30s RSSI 低于 -75dBm** → 记录事件日志并尝试主动重连（按第 33 条退避路径），防止"连得上但用不了"的假连接；恢复后继续正常监控。
33. **TCP 连接断开 / 心跳超时**：
    - 记录断线原因与时间，更新主机候选列表（当前主机置顶）。
    - 立即尝试重连候选主机（间隔按指数退避 + 抖动：1s、2s、4s、8s、16s、30s 上限，叠加 0~5s 抖动）。
    - 30 秒内未成功 → 切换回第三阶段（mDNS → 组播 → 候选列表）重新发现主机。
    - 发现成功后重新执行第四阶段（重新 hello，携带上次 session_id）。
    - **收到 busy 拒绝** → 按 60s 长退避重试（区别于普通断线退避）。
34. **WiFi 断开**（路由器重启等）：
    - 自动按 reason code 分类 + 退避策略重连已保存的 WiFi（同 3.1 节第 5 条）。
    - 连续 5 次失败 → 回到第一阶段重新判断（可能进入配网模式）。
    - 重连成功 → 自动进入第三阶段，无需重新配网。
35. **组播/mDNS 全失败**：按 3.3 节第 26 条循环，退避上限 30 秒，避免风暴。
36. **收到 host_bye**：立即停止等待通告，转主机候选列表直连（同 3.3 节第 27 条），并进入 30s 快速轮询以捕捉上位机重启后的新通告。
37. **看门狗**：状态机每个状态设置最大驻留时间；超时未迁移 → 记录错误日志并软重启设备（模拟环境中输出警告并回到第一阶段）。
38. **防风暴机制**：所有重连/重试均使用"指数退避 + 抖动"；配合上电错峰（3.1 节第 3 条），多设备同时断线/上电时自然错峰，避免同步重连压垮上位机。

#### 3.5.3 上位机侧

![Fig001B 上位机连接保障流程](figures/Fig001B_上位机连接保障流程.png)

*图 Fig001B：上位机连接保障流程。mDNS 注册 + 组播通告（退出前广播 host_bye）→ 等待设备连接 → device_hello 校验 → host_ack → 心跳监控与注册表管理。*

39. 设备注册表管理：
    - 维护 设备ID → 连接 的映射；同一设备重复连接时自动清理旧连接（设备重连后旧 socket 立即释放，配合 hello 的 session_id 续接语义）。
    - 心跳超时（15 秒无报文）→ 标记设备离线，保留注册信息供重连。
    - 连接数上限（默认 16，可配置）；超限时回复 `status=busy` 并记录拒绝日志。
40. 上位机重启：恢复组播/mDNS 通告后，设备通过 候选列表直连 → 组播 路径自动重连，无需重新配网（设备侧自动完成）。上位机**正常退出前必须广播 host_bye**（异常崩溃时由心跳超时兜底）。
41. **设备质量统计（新增）**：注册表按设备记录 心跳丢包率（ping seq 连续性）、重连次数、最近 RSSI、最后上线时间，供界面/日志展示（可观测性，与 5.2 节配合）。

## 5. 横切保障机制

> 本章机制贯穿全部五个阶段，不属于单一阶段，故独立成章：多设备管理、可观测性、安全、配置管理、传输健壮性。

### 5.1 多设备场景

42. 每台设备的 `Modu_XXXX` 热点名不同（MAC 后 4 位不同），且 WPA2 密码为每台设备唯一，上位机通过热点名区分设备并串行配网。
43. 配网完成后所有设备在同一 WiFi 下，通过 mDNS/组播拿到上位机地址，各自建立独立的 TCP 连接。
44. 上位机 TCP 服务器同时维护多个客户端连接（上限 16），每连接独立心跳监控。
45. 设备离线/上线由上位机注册表统一呈现（日志/界面），断线重连后自动恢复在线状态。

### 5.2 可观测性与诊断（v2 新增）

46. **事件日志环形缓冲**：设备在 NVS 持久化最近 50 条关键事件（上电、配网成功/失败、WiFi 断开及 reason code、TCP 断开、重连、RSSI 告警、看门狗重启），每条含时间戳（NTP 同步前为 boot 相对时间）。掉电不丢失，是现场排障的第一手资料。
47. **诊断上报**：上位机可对已连接设备发送 `{"cmd":"diag_query"}`；设备回复最近事件摘要与当前状态：

    ```json
    {"cmd":"diag_report","uptime":3600,"rssi":-58,"state":"connected","error_count":{"wifi_disconnects":3,"tcp_drops":1},"events":["..."],"last_event_time":1234}
    ```

    - `error_count`：自上次上电的累计错误计数；`events`：最近 10 条事件摘要。
    - 未连接设备可退化为串口/日志输出（模拟环境直接打印）。
48. 上位机侧：设备质量统计（第 41 条）与诊断数据对接展示，形成"状态 → 事件 → 统计"三层可观测性。

### 5.3 安全说明

51. **配网双因子认证（v2 增强）**：设备 AP 模式要求客户端先通过 热点 WPA2 密码（每设备唯一，PoP 语义）+ 一次性 PIN 会话认证，防止未授权设备连接热点或改写 WiFi 配置。
52. **一次性 PIN + 尝试锁定**：PIN 认证成功后作废（防重放）；连续 5 次失败关闭热点退避（防暴力破解）。
53. **设备接入认证（可选，默认关闭）**：上位机与设备共享预置 group key（写入双方配置）；device_hello 携带 `token`（group key 派生的一次性值），上位机校验通过才回复 host_ack。Demo 中通过配置文件开关控制。启用时 host_announce 的 HMAC 可同步开启（见 3.3 节第 24 条）。
54. **传输安全**：局域网内默认 TCP 明文 + 应用层认证（配网信道已由 WPA2 加密）。**TLS 加密与配网应用层加密（乐鑫 Security 1/2 思路：Curve25519/SRP6a + AES）列为远期增强**（ESP32-C2 算力有限，需评估开销）；Matter 风格的设备证书认证（DAC）作为 TLS 的基础设施一并评估。
55. **配置重置**：设备提供配网重置机制（长按按键 5 秒 / 串口命令），清除 NVS 中的 WiFi 配置并回到配网模式。

### 5.4 配置管理（v2 新增）

49. **配置 schema 版本**：NVS 配置携带版本号（当前 1）。固件升级后版本不匹配时按迁移规则升级（保留可迁移字段如 SSID/密码/候选列表），无法迁移的字段清除；整体无法迁移 → 清除配置并进入配网模式（最坏情况用户重新配网，不会死锁）。
50. **参数集中管理**：全部超时/阈值/端口集中在 4.2 节"参数配置表"，Demo 通过配置文件覆盖默认值；禁止在代码中散落硬编码。

### 5.5 传输健壮性（v3 新增）

> 成熟 IoT 协议（MQTT 固定头、Matter 消息帧、ESP Blufi）都为 TCP 链路定义了显式消息帧与尺寸上限；v2 的 JSON 报文未约定帧边界，两条报文粘连/截断时的行为依赖解析实现，本节补齐。

56. **消息帧**：所有 TCP 通道报文（配网 5935 与业务 5935）采用 **2 字节长度前缀（大端）+ JSON 负载**；UDP 的 host_announce/host_bye 为单数据报，天然成帧不加前缀。
57. **单消息上限**：JSON 负载上限 1024 字节；超长即视为畸形包。
58. **畸形包处理**：长度非法 / JSON 解析失败 / 未知 cmd → 记录事件日志并丢弃该消息；同一连接**连续 3 次**畸形包 → 主动断开该连接（防协议实现 bug 或恶意流量耗尽资源）。
59. **设备侧限速**：设备对自身发送做速率限制（默认 ≤50 msg/s），超限丢弃非心跳的低优先级消息并记录事件——既是设备 CPU/内存自保，也配合第 38 条的防风暴机制。
60. **协议版本协商**：见 3.4 节第 29 条（proto_ver / fw_min_req）；协议演进遵循"高版本兼容低版本"，host_ack 明确告知设备实际生效版本，避免新旧固件混用时静默失配。

### 6.2 附录 A：BLE 配网（可选增强，未纳入当前 Demo）

- 设备广播 BLE 服务（Blufi 协议），上位机通过蓝牙连接设备并发送 WiFi 凭据，**无需切换上位机网络、可多设备并行配网**。
- ESP32-C2 支持 BLE 5.0；PC 上位机需具备蓝牙适配器（主项目 Qt 已含 Bluetooth 模块）。
- 与 SoftAP 配网共享同一套 NVS 配置与后续流程（阶段三起完全一致）。
- 是否纳入后续版本由用户决策（见问题清单 Q13）。

### 6.3 附录 B：远期增强方向（v2 新增，均不纳入当前 Demo）

- **OTA 固件升级**：物联网设备标配能力；需增加固件分区、版本比对、升级失败回滚（ESP-IDF 原生支持），并解决"升级期间配网/连接中断"的衔接问题。**工厂离线场景走局域网升级通道**（设备从上位机/本地服务器拉取固件），不依赖互联网。
- **TLS 传输加密**：业务链路 mTLS（设备证书认证），依赖时间同步（局域网时间源，见 3.1 节第 8 条）与设备密钥烧录；ESP32-C2 需评估算力与内存开销。
- **配网应用层加密**：乐鑫 Security 1/2 方案（Curve25519/SRP6a 密钥协商 + AES-GCM），在 WPA2 传输安全之上提供端到端防护（防"热点密码被窥视"场景）。
- **Matter 风格设备认证**：出厂烧录设备认证证书（DAC），接入时由上位机/服务端校验，替代/增强 group key 方案。

### 6.4 附录 C：组播地址说明

`224.0.2.1` 属于 IANA 的 "AD HOC Block" 范围（224.0.2.0 ~ 224.0.255.255），可在局域网内使用，TTL 默认 1（仅限本地网段）。部分企业级网络可能禁用组播；本流程通过 一级 mDNS + 三级候选列表直连 提供兜底，组播不可用时仍可完成发现。
