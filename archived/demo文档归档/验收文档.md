# 验收文档 - 嵌入式设备组网配网流程 C++ Demo（v0.1.0）

## 1. 验收范围

**覆盖**：demo/ 独立 CMake 工程（构建、单测、启动测试）；协议实现（`协议文档.md` v1.1：13 种标准命令 + 通用消息占位框架 + 长度前缀帧 + 组播通告）；五阶段主链路（启动自检/SoftAP 配网/三级发现/注册握手心跳/异常自愈）；核心保障（PIN 认证、输入校验、多凭据 fallback、配网确认回滚、host_bye、busy 长退避、指数退避+抖动、RSSI 监测、事件日志、诊断上报、设备注册表与质量统计、参数配置）；抽象层双后端（sim 全功能 / esp32c2 骨架）；线程模型（host 1 线程 + device N 线程 + main）。

**不覆盖**：真实 WiFi/WLAN 操作、真实 mDNS 协议、真实 ESP32-C2 硬件（esp32c2 后端为骨架交付，标注"未硬件验证"）；BLE 配网、TLS、OTA、HMAC 防伪（流程文档附录，默认关闭）；主项目 TactileSense 的构建与功能（Demo 为独立工程，验收中声明互不影响）。

## 2. 验收环境

- 操作系统：Windows 10/11（开发机为 Windows 25H2）。
- 工具链：CMake ≥ 3.20；**Visual Studio 2022**（MSVC ≥ 19.30，C++17 + C11）；PowerShell；CMake 生成器强制 `-G "Visual Studio 17 2022" -A x64`。
- 构建配置：Debug（/W4 /WX 警告即错误）。
- 测试数据：`config/demo_config.json`（压缩时序）、`config/demo_scenario.json`（剧本）。
- 硬件：无（全模拟环境）；外部服务：无。
- 依赖：third_party/cjson、third_party/googletest（vendor 离线可用）。

## 3. 前置条件

- 仓库路径 `Document/Update/Research/嵌入式设备组网配网流程/demo/` 存在完整代码。
- 构建命令成功：`cmake -G "Visual Studio 17 2022" -A x64 -S . -B build && cmake --build build --config Debug -j8`。
- 工作目录 `demo/`（运行可执行文件时相对路径 config/run 可访问）。

- 失败标准：缺文件或用例失败。
- 证据要求：文件清单 + 测试输出。

### C. 启动测试（实际运行）

#### C1. 单设备完整链路（场景 A）
- 目的：验证进程内 host + device 线程完整走通五阶段。
- 前置条件：A 通过；工作目录 demo/。
- 操作步骤：`.\build\bin\provision_demo.exe --config config\demo_config.json --duration 45`，日志存 `run/launch_A.log`。
- 期望结果：退出码 0；日志依次出现：`AP started`（含 Modu_XXXX 与 PIN）→ `provision ok` → `state -> discovery` → `session established` → 至少 2 次 `ping` → `host_bye sent` → 退出摘要。
- 通过标准：全部标志行按序存在且退出码 0。
- 失败标准：缺标志行 / 非零退出 / 崩溃 / 卡死超时（60s）。
- 证据要求：launch_A.log + 标志行 grep 结果。

#### C2. 演示剧本（场景 B：故障注入与自愈）
- 目的：验证 wifi_disconnect / rssi_set / wifi_ok / host_stop 剧本动作与设备自愈。
- 操作步骤：`.\build\bin\provision_demo.exe --config config\demo_config.json --scenario config\demo_scenario.json --duration 90`，日志存 `run/launch_B.log`。
- 期望结果：日志含 `scenario: wifi_disconnect fired` → 设备 `reconnect`/状态回退事件 → `scenario: wifi_ok fired` → 设备重新 `session established`（含 session 续接日志）→ `scenario: rssi_set fired` → `rssi degraded` 事件（若剧本时序触发）→ `scenario: host_stop fired` → `host_bye sent`。
- 通过标准：wifi_disconnect→重连→session 恢复、host_stop→host_bye 两条链路的标志日志齐全；退出码 0。
- 失败标准：重连链路中断（60s 内未恢复 session）/ 无 host_bye / 非零退出。
- 证据要求：launch_B.log + 关键行摘录。

#### C3. 多设备（场景 C：3 台）
- 目的：验证多设备注册表与并发连接。
- 操作步骤：`\build\bin\provision_demo.exe --config config\demo_config.json --devices 3 --duration 25`，日志存 `run/launch_C.log`。
- 期望结果：3 台设备依次配网（`provision ok` ×3）→ 全部 `session established` → 退出码 0（host 退出时设备连接关闭、摘要 online=0 属正常下线语义）。
- 通过标准：3 台全部配网成功且全部 session established；退出码 0。
- 失败标准：任一设备未配网或未注册。
- 证据要求：launch_C.log + 关键行摘录。

#### C4a. GUI 模式启动（新增）
- 目的：验证 Qt 界面窗口创建、日志推送、状态刷新与控制面板可用。
- 前置条件：Qt6 可用（CMAKE_PREFIX_PATH 指向 Qt 安装）；Qt bin 在 PATH。
- 操作步骤：运行 `provision_demo.exe --config config\demo_config.json --duration 6`（GUI 模式）。
- 期望结果：窗口创建（日志含 `ui ready`）；日志区持续滚动 core 日志；设备状态表出现设备行；duration 到点自动优雅退出（watchdog 触发，host_bye 发出）。
- 通过标准：`ui ready` 日志出现；进程在 duration 后自行退出（不残留）；受限会话（无窗口系统）下退出码异常记阻塞，但 watchdog 兜底保证不残留进程。
- 失败标准：启动即崩溃 / 进程残留。
- 证据要求：运行日志（`ui ready` / `duration watchdog fired` / `exited`）。

#### C4. 命令行与帮助

## 6. 失败与阻塞处理

- 编译失败 → 退回阶段三修复（定位 SubStage）。
- 单测失败 → 定位对应 SubStage 修复并回归。
- 启动测试失败 → 退回阶段三；验收标准不清则先补验收文档。
- 阻塞（如组播被开发机屏蔽）：记录于验收报告，标记该项"阻塞"并给出旁证（候选直连兜底路径仍验证通过）；**不得默认通过**。
- 重试：任一失败最多 3 轮；仍失败暂停并重规划。
