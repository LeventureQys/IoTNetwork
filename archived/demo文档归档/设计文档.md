# 设计文档 - 嵌入式设备组网配网流程 C++ Demo（v0.1.0）

## 1. 背景与目标

在 `Document/Update/Research/嵌入式设备组网配网流程/demo/` 下开发一个独立 CMake 工程，用**单个可执行文件**验证《ESP32-C2 设备配网与连接保障流程》（v3 增强版，`../流程说明.md`）的完整五阶段主链路与核心保障机制。Demo 分两部分：上位机（host，C++17 核心开发）与嵌入式下位机（device，**纯 C99**），运行于同一进程、线程严格区分；网络访问通过纯 C99 抽象层（vtable 双后端：sim 后端本机运行 / esp32c2 后端供 ESP-IDF 移植），目标芯片 ESP32-C2（RISC-V 单核 120MHz、无 FPU、576KB SRAM）。

协议依据：`协议文档.md`（v1.1：13 种标准命令 + 通用消息占位框架 + 2 字节长度前缀帧 + UDP 组播通告）。

## 2. 总体架构

### 2.1 线程模型（严格区分）

```text
main 线程（C++）
 ├─ 加载配置（demo_config.json）+ 命令行
 ├─ 创建 N 台设备实例（每台：net_ctx + device_app，纯 C 模块，独立线程）
 ├─ 创建 host 实例（net_ctx + HostApp，C++）
 ├─ 启动 1 个 host 线程 → HostApp::Run()
 ├─ 启动 N 个 device 线程 → device_app_run()   （每设备一个线程）
 ├─ 剧本定时器（条件/绝对时间触发故障注入）
 ├─ --duration 到点 → 请求 host 优雅退出（广播 host_bye）→ 请求各 device 停止 → 汇合线程
 └─ 打印运行摘要，退出
```

- device C 模块内**零线程**：单线程事件循环（poll + 超时驱动），与 ESP32-C2 单核模型一致。
- 线程间唯一共享：sim 后端 SimWorld（虚拟 WiFi 介质、mDNS 注册表、虚拟 AP 表），全部互斥锁保护；日志全局互斥。
- 线程归属：所有 `[HOST]` 前缀日志仅 host 线程输出；`[DEV:n]` 仅第 n 台设备线程输出；`[MAIN]` 仅 main 线程输出。

### 2.3 虚拟网络语义（sim 后端）

- **虚拟 IP 翻译**：仅 sim 后端使用 device AP 逻辑地址 `192.168.1.1:5935`（真实监听 `127.0.0.1:20000+设备索引`）；host 虚拟 IP 默认 `192.168.1.50`（真实 `127.0.0.1:5935`）；配网成功后 device 虚拟 IP `192.168.1.100+索引`。连接虚拟地址时由 sim 后端翻译为真实地址，业务代码零感知。真实 Linux 配网端点由运行时热点的 DHCP router 地址决定，端口为 `5935`，不使用模拟地址常量。
- **虚拟 WiFi 介质**（SimWorld）：device 开启 AP 时注册 `Modu_XXXX` 虚拟热点（含 WPA2 密码、一次性 PIN、真实端口）；host `wifi_scan` 返回全部虚拟热点 + 目标 WiFi（`target_ssid`，配置）；STA 连接规则：SSID=目标 WiFi 且密码正确 → 成功；SSID 不存在 → 201；密码错误 → 202；剧本注入 → 按注入结果。
- **mDNS**：进程内注册表（host 注册 `host._tactile._tcp`，device 解析），模拟 Windows 原生 mDNS 不可用时的行为。
- **组播**：真实 UDP `224.0.2.1:5936`，全部实例 SO_REUSEADDR 重复绑定；剧本 `mcast_block` 注入时丢弃 device 侧收包（验证候选直连兜底）。
- **NVS**：每设备一个 JSON 文件（`nvs_dev<n>.json`），键值 blob 存取。

### 2.4 Linux 真实热点运行契约

- **地址规划**：配置首选地址，当前默认 AP 为 `10.42.0.1/24`、池为 `10.42.0.100` - `10.42.0.200`；与本机有效 IPv4 直连路由冲突时，依次尝试 `10.43.0.1/24`、`172.31.250.1/24`、`192.168.250.1/24` 三个固定 `/24` 备用段，并按 host offset 重定位 DHCP 池。路由采集失败、结果不完整或所有候选冲突时 fail-closed。
- **端点语义**：dnsmasq 将最终 AP 地址写入 DHCP router option 3 和 server identifier option 54；真实配网端点是 DHCP router`:5935`。`192.168.1.1:5935` 只属于 sim 后端，不得用于真实 Linux 地址规划。
- **配置语义**：热点配置缺失、格式或字段非法、工作目录不可访问时 fail-closed，不使用部分配置、不回退模拟后端。NAT 默认 `false`。
- **单实例与 readiness**：真实模式持有 `${work_dir}/modu_linux_hotspot.lock`。热点 ready 前必须验证 hostapd PID/进程身份、AP 接口模式、最终 IPv4/掩码回读，以及 dnsmasq PID/进程身份和该进程的 UDP 67 监听；任一步失败均逆序回滚本事务资源。
- **防火墙与 NAT**：部署环境负责 INPUT/OUTPUT/FORWARD，必须放行 `ap0` UDP 67 和 TCP 5935，应用不修改过滤规则。显式开启 NAT 时，部署环境还需启用 IPv4 forwarding 并配置 FORWARD；应用只管理自身精确 MASQUERADE 规则。
- **最终验收**：进程或 readiness 成功不能替代客户端验证；真实无线客户端必须完成 DHCP `DISCOVER/OFFER/REQUEST/ACK`，取得最终 router，并连接 router`:5935`。

**device_app 事件循环（device_app.c 内部）**：

```text
while (!stop_flag) {
    now = net_time_ms();
    if (now >= next_tick) run_state_machine_once();   /* 状态机推进，见 4.9 */
    /* 非阻塞轮询当前状态的 I/O 源（各子模块提供 *_poll）：
       AP 监听 accept / 配网连接收包 / 组播收包 / 业务 socket 收包 */
    poll_timeout = 计算到下一个定时事件的最小毫秒（10ms 下限）;
    sleep_or_poll(poll_timeout);                     /* sim 后端 sleep；真实环境可换 select */
}
```

- 每轮事件循环只处理**一个** I/O 事件（防饿死），随后回到循环头。
- 收包统一入口：`device_app_handle_rx(device_app_t *app, void *sock, int is_business)`：用 frame_parse 累积解析，畸形包计数（`malformed_count`，连续 3 次断开该连接），完整帧 → cJSON 解析 → 按 `cmd` 分发：`auth`/`wifi_config`/`close_ap` → provision；`pong`/`diag_query`/`host_ack` → session；`app_data` → 日志后丢弃（通用占位）；未知 `vendor_*`/未知命令 → request 型回通用占位应答 `{"cmd":"<name>","data":{"status":"unsupported"}}`、notification 型仅日志——**未知命令不计畸形**（协议文档 2.6 前向兼容）；对端发起方向消息（`device_hello`/`ping`/`diag_report`）属协议错误 → 畸形计数；限速检查（非心跳消息超过速率 → 丢弃 + 事件日志）。

### 4.9 五阶段状态机（device_app.c）

| 状态 | 进入条件 | 行为 | 迁移 |
|------|----------|------|------|
| BOOT | 创建后 | 读 NVS（wifi_creds 凭据 + host_candidates + evlog）；schema 版本校验；上电错峰延迟 rand(0, power_on_jitter_max)；未确认凭据回滚（Q-D5）；无凭据 → AP_PROVISION；有凭据 → STA_JOIN | STA_JOIN / AP_PROVISION |
| STA_JOIN | 有凭据 | 依次尝试 creds[active]（reason 分类）：OK → DISCOVERY；202/203/204（不可恢复）→ 记日志切下一凭据或 AP_PROVISION；201/205（可恢复）→ 退避重试 wifi_retry_max 次后切下一凭据；全部耗尽 → AP_PROVISION；多凭据 fallback（v3） | DISCOVERY / AP_PROVISION / STA_JOIN(重试) |
| AP_PROVISION | 进入配网 | 开 AP（SSID=Modu_XXXX、WPA2 密码、生成一次性 PIN）；AP TCP 监听；prov_server_poll 处理 auth/wifi_config；wifi_config 校验通过 → 尝试连目标 WiFi（reason 分类）→ 成功：写 NVS（未确认）+ wifi_result ok；失败：wifi_result fail 保持 AP；close_ap → DISCOVERY；ap_idle 超时 → 关 AP，退避 provision_ap_backoff → BOOT | DISCOVERY / BOOT |
| DISCOVERY | 配网完成/重连发现 | 一级 mDNS resolve（2s 超时）→ 二级组播监听（快速窗口 500ms，之后 1s）→ 三级 NVS 候选直连（candidate_timeout 未发现）；host_announce 校验 proto/seq；host_bye → 立即候选直连 + 30s 快速窗口；成功 → CONNECT；全失败 → 退避循环 | CONNECT / DISCOVERY(重试) |
| CONNECT | 拿到 host 地址 | tcp_connect(host)；成功 → 发 device_hello（重连带 session_id）；等 host_ack（hello_timeout）：ok → SESSION（保存 session_id/heartbeat/server_time 校时/proto_ver）；busy → 关连接 busy_backoff 后重试；fail → 关连接回 DISCOVERY；超时 → 关连接重试 | SESSION / CONNECT / DISCOVERY |
| SESSION | ack ok | 每 heartbeat_interval 发 ping{seq++}；收 pong/下行刷新 last_rx；heartbeat_dead 无报文 → HEAL；收 diag_query → 发 diag_report；收下行业务数据（本 Demo 仅 pong/diag_query，未知 cmd 忽略并计畸形） | HEAL |
| HEAL | 断线/心跳超时 | 记录事件 + 更新候选列表（host 置顶）；reconnect 退避重连（base×2^n cap + jitter）：成功 → CONNECT（带 session_id）；连续 reconnect_to_discovery_ms 未成功 → DISCOVERY；WiFi 断开（STA_JOIN 语义）→ 按 reason 处理；RSSI 连续劣化 → 事件日志 + 主动重连 | CONNECT / DISCOVERY / STA_JOIN |

- 看门狗：每状态 `state_enter_ms` 记录；驻留超过 `watchdog_state_timeout_ms` 且非等待外部输入（AP 等待、退避中）→ WARN 日志 + 事件日志（不软重启，Q1 方案 B 最小实现）。
- 事件日志：全部关键事件（上电/配网成败/WiFi 断开 reason/TCP 断开/重连/RSSI 告警/看门狗）调 `evlog_record`。

### 4.16 剧本（scenario）契约（main 线程执行）

```json
// config 中 scenario 数组元素：
{ "when": "device_state", "eq": "ap_provision", "then": { "action": "wifi_auth_fail" } }
{ "when": "at_ms", "at": 15000, "then": { "action": "wifi_disconnect", "args": {"device": 0} } }
```

| action | 语义 | 实现（sim 后端 inject） |
|--------|------|------------------------|
| `wifi_disconnect` | 目标 WiFi 断开 | SimWorld 标记目标网络不可用 → STA 断开（设备触发 reason 处理） |
| `wifi_auth_fail` | 目标 WiFi 密码错误（配网验证阶段） | SimWorld 注入认证失败（持续到 wifi_ok 恢复） |
| `wifi_ok` | 恢复目标 WiFi | 撤销上述注入 |
| `rssi_set` | 设置 RSSI 值（args.rssi） | SimWorld 覆盖设备 RSSI 读数 |
| `mcast_block` / `mcast_unblock` | 屏蔽/恢复组播收包 | sim 后端丢弃 device 侧组播收包 |
| `host_stop` | host 优雅退出 | main 调 hostApp.RequestStop() → host_bye 广播 |
| `host_crash` | host 直接终止（无 host_bye） | 销毁 HostApp（socket 关闭）→ 设备心跳超时兜底 |
| `nvs_unconfirmed_reboot` | 未确认凭据重启 | 销毁 device 实例 → 重建（NVS 保留） |
| `fw_version_old` | 设备固件版本改 0.9.0 | 重启设备实例前改配置 |
| `proto_ver_mismatch` | 设备 proto_ver 改 2 | 同上 |
| `busy_inject` | 临时降低 host_max_conn | HostApp 读取注入值 |

## 8. 错误处理契约（全局）

- C 模块错误返回：负错误码（DEMO_ERR_* / 抽象层接口语义），0 表示成功；关键失败必须 `evlog_record` + WARN/ERROR 日志。
- 非阻塞语义：recv 无数据返回 `DEMO_ERR_AGAIN`（调用方继续轮询），不做阻塞等待。
- 超时契约：所有网络等待必须有超时（参数表），超时后按状态机迁移规则处理，禁止无限等待。
- 线程安全：仅 SimWorld 与日志需要锁；device 各实例互不共享（NVS 文件按实例隔离）。
- 内存：device 产品代码零 malloc（固定数组）；host/sim 可用 STL；cJSON 动态内存仅用于短生命周期消息解析。

## 8.5 UI 界面（Qt Widgets，与 core 解耦）

- **解耦原则**：core（common/device/host/net_sim）**零 Qt 依赖**（CMake 层保证：core 目标不链接 Qt）；UI 层 `ui/` 只依赖 core 公开接口与两类订阅机制。
- **订阅机制**（core 新增，均为纯 C/C++）：
  - 日志流：`log_set_sink()` 注册回调，每条日志锁外回调（UI 经 LogModel 入队展示）。
  - 状态快照：device 增加原子快照字段（`snap_state/snap_rssi/snap_uptime_s`，事件循环 500ms 节流更新）；host 注册表新增 `Snapshot()`（锁内完整拷贝）。
- **桥接层**：`ui/ui_bridge.h`（不依赖 Qt）封装状态查询（设备快照 / 注册表快照）与控制命令（配网 / 注入 / 停止）。
- **Qt 层**：MainWindow（日志区 + 设备表 + 控制面板）、LogModel、DeviceModel；QTimer 驱动刷新与剧本；duration 由独立 watchdog 线程兜底（事件循环受限时强制退出，防残留进程）。
- **运行模式**：默认 GUI（`--no-gui` 回退控制台，自动化验收路径不变）；Qt6 未找到自动回退控制台。

## 9. 假设与边界

- Demo 验证对象为协议与流程逻辑；WiFi 介质、RSSI、mDNS 为模拟实现（Q2 方案 B）。
- esp32c2 后端为骨架交付（未硬件验证），不参与宿主机构建与验收（Q12）。
